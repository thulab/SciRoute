# DatasetSnapshot 与 Arrow coverage index（A07）

`prepare_dataset_snapshot` 接收已发布版本 catalog、存储实例及显式数据集绑定。`SourceSelector` 可在准备时选择 latest，但传入的 shard 清单必须与本次 catalog 结果完全一致；输出只保存精确 path/version，不会在 epoch 或窗口查询中再次解析 latest。HF `state.json` 的 `_data_files` 顺序必须与清单逐项一致。当前不能核实 `_indices_data_files` 到逻辑行的映射，因此非空 indices 清单会明确拒绝；空数组或 `null` 表示没有 indices。逻辑行按 `logical_row=0..N-1` 排列，允许映射到相同物理行，但不同逻辑序列的身份必须显式声明，不能用相同 label 或相邻文件猜测续接。`state.json` 读取器支持标准 JSON 字符串转义（包括 Unicode 代理对），并拒绝尾逗号。

快照的**内容指纹**由数据集 ID、**有序** shard 的精确版本、完整 manifest 身份/元数据，以及逐行的 series/entity、目标字段、全局 step、时间和 channel 映射组成；它不包含 PID、随机 nonce 或存储 backend namespace。同一份声明在不同进程或 backend 实例中生成相同指纹，因此持久化的 `TrainingViewSpec.snapshot_fingerprint` 和由其构成的 sample ID 可以重用。旧版含随机值的指纹与新版不兼容，已有视图绑定和预期 sample ID 需重新生成一次。内容指纹本身不能证明两个数据库是同一存储实例，也不对 payload 字节做哈希：`DatasetSnapshot` 另带进程实例身份和 backend namespace，`validate_dataset_snapshot_runtime` 可不打开全部 shard 就检查内容与运行时绑定；source 复核、index/view 预校验和窗口组装也会检查相应身份。每个进程仍须针对自己的 backend 重新准备快照和索引。sidecar 使用内容指纹、进程身份和 backend namespace 组成的独立运行时绑定；新进程或另一 backend 会重建 sidecar，避免 path/version/manifest 恰好相同时误命中。跨进程共享 sidecar 需要未来提供稳定的存储实例身份。`DatasetSnapshot` 目前是可编辑的公开结构；索引准备、source 检查和视图预校验会重算内容指纹，内容被改动但指纹未更新时返回 `StalePlan`，在读取或发布 sidecar 前停止。语义绑定与匿名 Arrow 物理地址分离：`SnapshotRowBinding` 中的 `n_channels`、`length`、label、unit、original channel ordinal 和时间声明由可信数据集 manifest/调用方提供，索引准备再将其与已摄取 layout 的 O/I offsets、List 形状和有效位交叉校验。当前 API 不从任意 Arrow 标量辅助列自动推断这些语义；也不把 `item_id` 相同当作同一 series。若后续引入自动导入器，必须产出相同的显式绑定，并且只读取所需辅助列和索引，不扫 target values。

`prepare_dataset_coverage_index` 是显式的、一次性的准备入口。它先验证每个精确版本仍存在，然后优先读取匹配指纹的 sidecar；缺失、校验错误或协议不匹配时在此入口重建。重建对每个涉及的 shard 读取一次 layout，**不读取 target payload**。每个 coverage span 包含 series、逻辑行、精确 shard/batch/row、原 channel ordinal 到物理 ordinal 的映射、全局半开 step 区间及物理行的起始 step；`lookup` 先按 series/channel 定位范围，再二分到起始 step，返回剪裁后的多文件片段，A08 可用 `clipped.begin - source_step_begin` 计算行内位置。空洞返回 `InvalidDomainSlice`，不会跨独立 series 拼接。

同一 series/channel 的覆盖不允许重叠。不同原 channel 可以在同一 step 区间由不同文件分片，必须显式声明物理映射。对同一 series 的每个 distinct step 区间，所有变量分片行合起来必须声明该 series 的完整 channel identity 集合；某段没有物理 channel 时，要显式声明 `physical_ordinal = null`。未声明的缺口在索引准备阶段报 `InvalidQuery`，不会延迟到窗口查找时变成 `InvalidDomainSlice`；显式缺失则保留覆盖 span，供 `Mask`/`RejectWindow` 在窗口阶段处理。此校验在加载 sidecar 前执行。相邻分段只有在相同 series、step 恰好相接且时间绑定一致时才构成连续覆盖；固定 cadence 会验证跨段下一时间点，step-only 依赖声明的全局 step 起点。单段可声明严格递增的显式时间戳；跨文件非固定时间暂不接受，需要后续明确 calendar 规则。`validate_snapshot_view` 在窗口准备前核对指纹和各 series 的所选 channel identity/label，并同样拒绝遗漏的段声明。null series、null channel、缺失 channel 在 span 中分别标记；leaf null 留给 A08 值解码时处理。

sidecar 是带版本头、运行时绑定与 SHA-256 的有界二进制文件，先以 `0600` 写独立临时文件，写完后设为 `0644`、fsync，再同目录原子 rename；目录权限仍决定其他用户能否访问。写入失败只影响缓存，已重建的内存索引仍可使用。coverage 协议为 `iotdbfs-arrow-coverage/3`：加载时要求 span 总数等于声明的 channel 总数，并逐项核对每个 `(logical row, field, original ordinal)` 恰好出现一次。旧 `/1`、`/2` sidecar 或有效 checksum 但缺少 span 的 sidecar 都在显式准备阶段重建。窗口 lookup 不访问 source 或重新扫描索引。当前 read handle 仅保留 manifest，**不是防删除 lease**；训练使用期间必须禁止对快照中的版本进行管理性删除或 rename。删除后准备/显式检查返回 `SourceNotFound`，不会悄悄转到新版本；不承诺删除后的 cache miss 仍可重放。

边界：A07 只准备身份和 coverage，不组装值、窗口或变换。A08 将把这些 span 接入按需解码与跨文件窗口组装。辅助标量字段的自动探测、存储内持久化 sidecar、calendar/不规则跨段续接仍需单独实现；当前调用方必须提供经过审阅的数据集语义清单。
