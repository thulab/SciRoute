# 多实验训练视图的共享对照

本实验检验当前 IoTDB-FS 是否能让不同训练实验复用未变换的基础数据，并区分资源节省与端到端收益。冻结生产二进制，复用 Electricity 原始 Arrow 和 128 点 step-major、未压缩派生布局。所有实验都生成私有、连续的 Float32 input/target 和 bool mask，按同一训练统计标准化。

## 负载与对照

四个实验分别使用 L/H=64/24、96/24、128/48、192/48；投影为通道 `[0,64)`、`[32,128)`、`[64,192)`、逆序 `[128,192)`。每个实验有独立 experiment_id、view_id、prepared ID。每轮 24 请求，每请求两个窗口；种子固定为 20260930，抽样规则在计时前冻结。

- overlap：四个实验从相同基准 anchor 加 0/7/14/21 步偏移，检验不同窗口与投影的基础片段复用。
- disjoint：实验间偏移 16,000 步；完整窗口及 SM128 物理块不重叠，作为共享的负对照。此对照仅运行 SM128，避免原始大 batch 边界产生隐藏复用。
- 原始布局与 SM128 都运行 overlap，观察细通道 tile 的投影选择性与包含全部 370 通道的训练块之间的取舍。

每个负载运行 FS-private、FS-shared、typed-private、typed-shared。FS-private 同时保留四个私有读取器，OS mmap 页缓存仍由系统自然共享；FS-shared 用一个共同读取器和解码缓存，是普通 FS 的强共享对照。typed-shared 的四个视图在一个 QueryRuntime 中串行轮转。typed-private 每个实验使用新 daemon，分别运行再求和，是隔离缓存的参考成本，不是并发 makespan。

共享预算为 1 GiB，私有预算为每实验 256 MiB，总预算相同。生产二进制保留 16,384 条目的上限，预期高于本轮工作集；负载记录 eviction，以确认条目与字节上限是否实际生效。FS 和 typed 的解码及输出实现不同：FS 读取完整 IPC batch，原始 typed 可以选择通道 tile，因此跨后端差异不能全部解释为数据库机制，也不能代表最优的 FS 投影实现。

“预算相同”指配置额度；两后端记账范围不同。Typed 还约束 layout、在途和临时内存，FS 主要限制保留的 decoded arrays，不限制映射页、临时输出或全部进程内存。比较共享与私有的收益应优先在同一后端内进行，不能据此声称跨后端等 RAM 容量优势。

## 计时与正确性

三次独立重复，反转布局、后端及共享方式的执行顺序；每个上下文执行一次应用缓存冷遍和一次暖遍。不清理 OS/数据库缓存，不称为磁盘冷实验。新视图的构造和 prepare 单列；冷端到端成本为构造、prepare 与执行耗时之和。暖遍复用 prepared ID，但每次窗口结果路径及时释放，不复用最终结果。

三轮使用同一固定轨迹，是计时重复而非三个独立随机工作负载。缓存占用的记录口径为 typed 一遍中请求结束后的最大记账值、FS 一遍结束值；压力下不能把两者当作同口径 RSS 或峰值比较。

按请求逐位比较标准化 Float32 和 mask，检查形状、通道顺序和连续性。验证计时排除在请求 wall time 外。记录读取字节、range/API 次数、解码次数、缓存淘汰、驻留缓存记账字节及各执行阶段。缓存记账不等于进程 RSS，不包含所有编译上下文、结果存储和客户端输出。

现有 profile 的 runtime_delta 是 daemon 全局起止差值，不能在重叠请求中求和。本轮串行交错并严格检查 profile 未重叠，不宣称并发吞吐、公平性或 DDP 扩展性。Electricity 单文件、单序列、显式坐标只能验证时间覆盖定位和变量投影；跨文件元数据索引优势需要独立实验。

执行脚本：`tests/benchmarks/arrow_training/run_shared_training_views.py`。使用前一轮 `layout-system-control-20260930/artifacts.json` 固定 source/version/hash，实验完成后恢复专用 mount 的原配置。

## 缓存压力补充对照

SM128 的 overlap 再以总预算 128 MiB、每私有实验 32 MiB 运行三轮。每个实验改为 64 请求，基准 anchor 从 `[1024,65000)` 抽样；其余窗口、变量、输出和准备规则相同。扩大时间范围和请求数，使工作集超过私有缓存。该预算是机制消融参数，不代表服务器内存耗尽，也不限制 OS 页缓存。检查共享的工作集是否容纳于预算，以及私有缓存因重复保存基础块而发生的驱逐、暖遍再读取和再解码。

压力下允许暖遍 I/O；仍必须满足逐位正确性、完整请求和样本数。将 FS-shared 同样纳入，避免将一般共享缓存收益描述成数据库独占优势。主实验保留不重叠时间区间的负对照。

补充运行参数：`--cache-mib 128 --cases sm128-overlap --requests 64 --anchor-stop 65000`。默认主实验为 `--cache-mib 1024 --cases all`。两组分别汇总，不混合估计。

前置 32 MiB 总预算／8 MiB 私有预算探测在 typed layout 加载时返回 `fragment exceeds runtime memory budget`：当前保守 layout 解析预留超过私有预算。该失败保留为边界证据，不纳入成功性能统计；之后扩大预算与工作集，而非修改生产内存检查。
