# GRIB 解码后渲染复用方案

2026-10-22。状态：用户确认后已完成候选实现、88 项本地／115 项聚焦／1,841 项完整单测和 288 条固定查询独立审计；完整计时缺乏稳定加速，按约回退正式源码，候选及原始证据保留服务器。N128 C/A 完整 R 为 0.907574，原始完整 T 为 1.082352，两轮 T 变慢。详见[完整验收报告](../reports/grib-render-reuse-20261022.md)。以下记录已确认且实际执行的候选边界，不代表当前主线已支持该功能。

## 已确认的重复工作

| 位置 | 当前工作 | 本轮处理 |
| --- | --- | --- |
| `GribQueryKernel::render_grid` | 每次选择轴范围；循环经度另建布尔数组；重新计算窗口 | 编译不可变几何映射，复用窗口、原生下标和选中轴描述 |
| 同上，非插值取值 | 原生 Float64 场 → 新建 double 窗口数组 → Float32 输出数组 | 直接从原生场填充最终 dtype，不分配 double 窗口中间数组 |
| 同上，坐标 | 无论投影是否包含坐标，都构造两条输出轴 | 由投影决定需要哪些派生数组；形状与 origin 独立保留 |
| `GribQueryCursor::next_grid` | 从已生成的最终 dtype 数组再次 `array_slice`，坐标再展开为逐点列 | 完整单 batch 移动最终值数组；分 batch 保持边界，避免额外全量 double 中间数组；仅生成实际投影的坐标列 |
| `decode_native_field` / `gribUtils` | native miss 时 ecCodes 解码 Float64，轴和值移动进原生场 | 沿用现有内容缓存与解码算法，不修改旧 POSIX crop 内核 |

代码依据：`src/formats/grib/GribQueryKernel.cpp` 的 `selected_values`、`render_grid`；`src/formats/grib/GribFormatQueryAdapter.cpp` 的 `decode_cached_grid`、`grid_axis_slice`、`next_grid`。此前有效固定组的暖取值已是 native field 命中、零新增解码，见 [发现优化报告](../reports/grib-discovery-reuse-20261022.md)。

FM1 的当前两个 GRIB case 仅投影 `grib.data.value`，读取命中的完整 64×64 message，没有 ROI 或插值。因此固定组主要验收分配／复制消除；不能把 ROI／插值单测或局部计时解释为这些 case 的完整查询收益。

## 已确认的候选实现边界

1. **先消除副本。** 保持现有 worker 内的渲染调度，直接写最终 Float32／Float64 owned 数组，保留原采样顺序、NaN、cast 和双线性算术语义。值、纬度、经度按投影分别生成，仍执行原有 native 加载、形状检查和逻辑费用，不能因未投影而隐藏既有错误。单 batch 转移所有权前保存总行数和消费状态；分批暂保留必要的最终 dtype 切片，保持行边界、顺序、domain、provenance 与取消语义，不借用可变的 native 值数组。首版不把渲染移至 cursor 主线程，避免撤掉原有 message 级并行。
2. **每个 native 内容条目至多一个最近几何映射。** 映射只含窗口、下标／轴描述和输出形状，不含值、mask、ROI 答案、QuerySource、账本或执行租约。槽隐式绑定同一不可变 native field；同编码内容跨精确版本共享时可复用，不同内容即使网格相同也暂不共用。避免另建几何全局池和热查询轴哈希。完整非插值网格直接使用原生几何和五标量窗口，不为其新增缓存查找、锁或分配；缓存仅用于实际需要筛选／变换的几何。
3. **精确映射身份。** 显式键包含完整 crop（包括 extend_equal）、按现行语义整理的 slices（轴、上下界存在性、开闭、Float64 位模式）与全部插值参数。dtype、projection 和 batch 大小不改变几何；缓存不能持有首请求的投影／能力。原生网格身份由所属 native field 固定，不仅以 Ni/Nj 匹配。
4. **额度不增加。** 新映射及管理信息计入既有 native cache 64 MiB 总额度；每内容至多一项，数量随既有 native 条目上限约束。替换或淘汰后仍被请求持有的新增映射继续计费，直到最后引用释放；不收紧原 native field 临时／外部 pin 的历史分配模型。不够预算或可选映射分配失败时，只停止映射保留，使用本次有界渲染；不保留失败。不能为了缓存命中跳过每次精确来源的权限、准入、取消或费用。
5. **格式边界保持。** 实现与状态位于 GRIB Adapter／Kernel；不改公共 LogicalArray 所有权协议、持久格式、客户端协议、HDF5、数据库连接池或并发数。首版几何槽仅保留非插值窗口；插值仍沿用原 double 采样表达式与顺序，仅在写入时生成最终 dtype，不保存插值映射。

## 验证与消融

| 配置 | 内容 |
| --- | --- |
| A | 本轮开始时已验收产品，使用已有 `format_catalog` 发现和原 typed 取值 |
| B | 仅减少渲染中间数组、非投影坐标与完整 batch 值复制 |
| C | B 加同 native 内容条目的几何映射复用 |

消融只新增实现／运行身份，发现请求、取值请求、封印语料、oracle、FS-index、输出与资源协议保持一致。用于切换消融的配置只控制可选渲染优化，不能改变权限、预算、结果语义；不引入新旧协议兼容分支。

当前两个完整非插值固定 case 的 B/C 应走相同的无映射缓存快路。其消融能检验整合是否回退，不能证明跨请求 ROI 映射缓存的性能收益；该机制先以功能测试和独立局部诊断验证，不擅自新增正式 ROI case。

- 先做本地功能／机制验证：F32/F64、仅值／仅坐标／混合投影、单 batch／分 batch、空窗口、相邻及跨日期线窗口、边界开闭、纬轴方向、NaN、插值、不同几何、相同内容跨版本与 namespace、并发映射替换、容量不足、退役映射 pin、预算失败和取消。比较 owned 值／mask、坐标、domain、顺序及逐来源费用。
- 使用既有 `G-H1-N8` 做单 campaign 小探针，先验证完整输出与资源恢复；通过后才复测独立 `G-H1-N128` 三 campaign。不是 N512 内 C128，不重新生成、发布语料或构建 FS-index，不扩展固定 case。
- 沿用两核共享、2 GiB 查询组和原数据库配置／许可证；记录实际资源、完整 d/q/T、R/Rd/Rq、构建输入与恢复证据。每臂 2 预热＋10 正式，轮换配置顺序，保留全部观测。
- 新增计数说明 double 中间数组、坐标构造、值复制及映射命中／旁路，局部渲染计时仅解释机制。是否保留依据同轮配对的完整 R 与原始完整 T；明显减慢的部分回退，不用历史最小值或局部加速替代完整查询验收。
