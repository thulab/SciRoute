## 1. 目标、证据与范围

首要目标是减少发现阶段反复从 IoTDB 取回同一批 manifest、marker 并重新验证的成本；其次是让不同版本共享完全相同的目录页、layout 与原始数据块。每个逻辑版本仍有独立身份、存活状态、权限和来源记录。

现有固定 N=128/K=2/D=4/depth=2 实验中，HDF5「发现＋完整命中单元取值」温热中位数为 **106.811351 ms**，同期 GRIB 为 **57.404444 ms**。HDF5 合并后的 manifest＋marker 阶段中位数约 **54.41 ms**；这已经是一条包含两个扫描分支的 SQL，而不是 128 次 RPC。完整请求中的发现／取值累计时间占比约 **82.91%／17.09%**。这些数据来自同一轮固定实验，不保证新设计能够直接减去 54.41 ms；相关阶段与总时间的中位数不能相减或相加推导收益。证据见[合并读取消融](../reports/hdf5-manifest-marker-ablation-20261015.md)。

该负载每路径只有一个实验版本，因此跨版本 payload 去重本身不能解释或消除当前发现瓶颈。实施应先完成目录一致性与验证复用，再实现数据块共享，不等待差分压缩。

范围包含：版本目录、发布证明、内容身份、解析／完整性验证缓存、直接范围映射、删除后的安全回收、显式迁移与公平消融。不包含：字节差分、数值差分、历史版本重建链、多 writer 分布式事务、跨租户去重、任意历史快照恢复为当前目录，也不改变原文件的逐字节内容。

## 2. 参考工作与采用边界

| 工作 | 经过核对的机制 | 本项目借鉴 | 不直接照搬 |
|---|---|---|---|
| [Apache Iceberg specification](https://iceberg.apache.org/spec/) | 不可变 metadata／manifest，快照引用可复用文件；通过原子 metadata 指针提交新状态 | 一个已提交目录根决定可见版本；提交前验证、提交后复用；查询冻结一个根 | Iceberg 的表快照不负责本项目的 POSIX 路径遍历、即时权限变化与源删除；IoTDB 是否具有可用的原子提交原语必须另行验证 |
| [ForkBase, PVLDB 2018](https://www.vldb.org/pvldb/vol11/p1137-wang.pdf) | SIRI／POS-Tree 通过稳定结构和内容身份共享相同页，版本直接引用树根 | 逻辑版本和物理内容分离；写时复制目录页；当前根直接寻址，不遍历版本链 | 首版不实现完整 POS-Tree、fork／merge 或使用论文中的旧哈希算法；普通有界 COW 树不宣称具备 SIRI 的全部性质 |

以下协议是针对本仓库提出的设计，不是两项工作的既有实现或性能承诺。参考借鉴集中在**不可变对象、已提交根、结构共享**，权限与撤销规则由 IoTDB-FS 自己定义。

## 4. 身份模型：内容共享不共享权限

引入以下内部对象；协议名、字段语义和 ContentId framing 在 V00 冻结，具体字节 codec 与 golden fixtures 在 V01 交付。

| 对象 | 最小字段与用途 |
|---|---|
| `NamespaceIdentity` | 创建 namespace 时持久生成的 UUID；存储重建／恢复的 incarnation。数据库端点是定位信息，不独自充当身份。不同数据库复制后应有独立 incarnation，避免旧缓存／句柄误用 |
| `NamespaceHead` | namespace、incarnation、提交序号、提交记录身份与目录根；一次完整提交的唯一可见性入口 |
| `CatalogRoot` | current-path 根、精确版本根、存活／tombstone 根、权限根及协议号；完整地绑定这些视图，不能分别读成混合代次 |
| `VersionBinding` | 原有 path/version、format、大小、不可变文件描述根、版本绑定封印；外部查询与 provenance 仍返回精确 path/version |
| `PermissionState` | 现行源 mode/uid/gid/is_dir、祖先目录搜索权限和各自的变更代次；不放入 payload 内容身份 |
| `FileDescriptor` | payload 范围映射根、layout 内容 ID、格式目录内容 ID／marker 证明、长度、协议／构建规则身份；不携带权限、外部路径或该次发布的版本号 |
| `ContentId` | SHA-256 的规范输入包含对象类型、编码协议、长度和实际字节；存储／缓存以 namespace 隔离，默认不跨 namespace 共享 |
| `VerifiedArtifact` | 内容 ID、验证规则版本、完整性状态、解析结果和实际持有字节；成功缓存按字节受限，失败结果不冒充成功证明 |
| `ReadContext` | 内部不可伪造的目录根引用、冻结精确版本、权限主体及证据、生命周期／预算；客户端只能提交查询，不能上传“已验证”标志 |

将现有单一 revision 的用途拆分为“内容描述身份”和“可变 namespace／权限代次”，保留对外 revision 字段及原错误语义。不能直接删掉 revision 校验后仍认为权限受到保护。

HDF5 当前发布封印摘要包含 path/version；它不能直接充当跨版本内容 ID。新设计使用两层证明：

1. 内层证明只绑定规范目录内容、layout 身份、协议、记录数和完整性状态，可在内容完全相同时复用。
2. 外层版本封印绑定 namespace、精确 path/version、大小、format 和内层内容根；每次发布／rename 重新产生。权限由同一提交的权限根绑定，不通过修改内容封印处理 chmod。

若现有 artifact 编码包含源路径、版本或其他身份，必须先明确拆分规则并发布新协议，不能只删除校验字段。不同物理偏移、类型、过滤器、语义规则或缺测策略不能因为“数值相同”而共享同一解码身份。缓存可以共享字节或解析对象，但错误归因、预算、权限和返回来源始终按各自版本计算。

## 5. 版本目录与提交机制

### 5.1 两种直接目录

- **当前路径目录**：按 path 与 format 选择范围定位当前可见版本及权限引用。Latest 保持现行“先格式筛选、再取最大 version、再应用文件／dataset 谓词”的次序；不能因新版不命中谓词而回退。不能用一个跨格式 latest 指针替代指定格式的最新版本。
- **精确版本目录**：`(path,version)` → 版本描述与可见状态。历史查询直接查找，不追溯父版本链。删除最新版本后选择仍存活且满足格式范围的最大 version；实际 FUSE 写入可能产生额外空版本，generic Latest 与 HDF5-filtered Latest 可以不同。V00 已用真实挂载与单测冻结此行为。
- 目录采用有界、确定编码、按键排序的 COW 页树；未变化子树可共享。首版允许普通平衡页树，要求最大页字节、条目数、树高和查询读取预算，不能把整个 namespace 序列化成每次更新的大 JSON。
- 文件格式目录与 namespace 版本目录分层：后者仅管理源身份和安全状态，dataset／message 属性及摘要仍由 adapter 提供。

保留旧根用于诊断／回收，不使已删除文件重新可查询。请求指定旧根不能跳过**当前**存活和权限检查；本计划不提供“旧快照绕过撤销”的入口。

### 5.2 发布与元数据修改顺序

```text
准备不可见对象／COW 页
  → 校验字节、格式目录、引用闭包和版本封印
  → 写入完整提交记录，确认所有被引用对象持久可读
  → 原子提交 NamespaceHead（线性化点）
  → 发布进程内当前根，失效受影响的授权证据
  → 返回成功
```

同一事务边界覆盖 publish、chmod/chown、目录权限、rename、精确版本删除、整路径删除及维护／迁移工具。内容变化产生新版本；权限变化产生新目录提交，但继续引用原内容。rename 改变路径绑定和祖先依赖，不能复用旧路径的权限结论。

**不能假定当前 IoTDB SDK 的多条 INSERT／UPDATE 是原子事务，也不能把进程 mutex 称作数据库 CAS。** V00 必须验证单行完整 head 记录的可见性、持久性与确认丢失行为；采用受控单 writer 时可串行提交，但仍需证明 crash 后不会出现半个 head。不可用时，先提出具备原子提交能力的元数据协调方案并确认，不用“最后写 published=true”加缓存代替该保证。

首版建议限定一个 namespace 所有写入口由同一 owner 进程服务；只读客户端经 owner 获取上下文。原本绕过 owner 的写入挂载、维护命令、后台 inode flush 必须被阻止或纳入提交协议。仅持有某主机的本地锁，不能证明其他主机停写；无法满足边界时不能开启该优化模式。

提交失败或确认不明时，在持久 head 中按提交 ID 确认结果后再响应／重试；不能在不确定状态下继续发放旧上下文。重启恢复只读取已提交根，不重放无限历史；不可达的 staging 对象稍后回收。inode SQL 行等物化视图若需要异步维护，只能作为派生视图；普通 FUSE、授权与 typed 查询不能各自把不同视图当作当前真相。该接线是上线前置条件。

## 6. 如何减少发现阶段重复重验

### 6.1 查询路径

1. 从 owner 获取当前完整目录根及短期内部上下文；同进程热路径可以复用已装载根。独立 reader 必须通过有界控制调用确认当前根，不能凭自己的 TTL 宣称“未变化”。
2. 从 current 或 exact 目录冻结源版本，并记录全部选中源及去重祖先的依赖。大小、format、封印、marker 证明来自同一提交。
3. 按请求 uid/gid/规范化补充组校验所有选中源与祖先权限。权限判断可使用同代次目录页，无需逐源 SQL；缓存命中仍计算请求逻辑预算。
4. 对格式目录，命中 `VerifiedArtifact` 时复用解析结果和完整性证明；未命中时有界批量读取，检查完整内容摘要与格式规则后入缓存。新请求不再为热目录单独读取 marker。
5. 按既有顺序验证封印、时间证据、目录状态，执行预编译谓词；保留结果顺序、类型／NULL 行为、候选和输出上限。时间未命中的已选源也不能跳过现行必需的封印／可用性检查。
6. 在返回发现结果或准入一个新取值执行前，于 owner 的提交同步边界检查上下文依赖。未变则准入；变化则按下表处理。拿到目录根不自动授权无限次 execute。

| 情况 | 需要做的工作 | 省去的工作 |
|---|---|---|
| 同一提交、目录内容热命中 | 代次／依赖检查、权限结论有效性检查、谓词与预算 | N 个 manifest 行和 marker 行的再次 SQL 读取、同内容 SHA-256／解析 |
| 仅不相关路径发生提交 | 先查有界变更集；证明本请求依赖未变后准入 | 重新读取所有候选内容 |
| 源／祖先权限变化 | 失效相关授权并重新判断；拒绝时 PermissionDenied | 内容解码／目录解析无需跟随 chmod 清空 |
| 冻结源删除或内容身份不符 | StalePlan；首次指定已不存在版本沿用现行 not-found 语义 | 不用新 latest 替代旧版本 |
| 变更集丢失、溢出或跨 incarnation | 有界重读全部依赖或明确失败；不以不完整增量作证明 | 不承诺此情况常数成本 |
| 目录内容冷 miss／发现损坏 | 校验完整对象与引用、报准确的来源与错误 | 不把失败缓存为成功 |

变更依赖包含**全部冻结候选**和祖先，不仅是最终 K 个命中源；否则会改变现有未命中源删除／权限错误的边界。Latest 在请求初始选择时冻结；新版本随后发布不自动替换已冻结的仍存活旧版本。需要重新开始选择时必须是显式新请求。

准入检查与提交序列化，但不持有全局 namespace 锁执行远端 I/O、解码或整段查询。源内容在内部执行租约期间不得物理回收。权限撤销与正在执行请求的先后顺序，以其准入／结果发布检查为线性化边界：撤销先完成则后续准入失败；已发布并打开的只读结果按现行句柄语义继续读。最终检查与结果注册／开放新句柄之间不能留下无保护窗口。

若执行期间有相关撤销，尚未对外发布的结果必须在发布时重验并丢弃失效结果；既有已打开 IPC 不追回已授权字节。独立的取值请求，即使使用上一请求的发现结果，也要取得新的存活／授权准入。

### 6.2 为什么这不是简单的缓存开关

当前合并 SQL 承担的是“授权返回后，冻结源和 marker 是否仍有效”的检查。只有满足以下条件，才能用已提交证明替换它：

- 内容与 marker 证明在发布前完整验证，发布后所有支持的接口禁止改写；新目录根绑定该事实。
- 所有改变源可见性、权限或路径关系的操作经过同一提交边界。
- 查询携带可验证根和依赖；缓存的内容身份与实时授权分离。
- 删除推迟物理回收，保证已准入执行不会读到被回收／复用的块。
- 重启、远端写入、恢复与确认不明不会产生错误的“代次未变”结论。

SHA-256 只能证明“读到的内容匹配预期”，不能证明“该版本现在仍存在且允许访问”。TTL 也不是提交一致性证明。直接 SQL 篡改不属于受控写入协议；默认 strict 保留现有审计边界，另提供显式全量校验工具，但不声称 strict 能发现所有等数量篡改。

### 6.3 成本边界

现路径近似为 `源目录 SQL + 授权 + N 源 manifest/marker 重验 + 目录缓存/谓词`。目标热路径为 `当前根确认 + 必要目录页 + 内存授权/谓词 + 准入检查`。

目标是消除**重复完整性 SQL**，不是把任意谓词发现都变成 O(K)：无可用摘要时，N 个源、每源 D 个单元的内存检查仍可能需要 O(ND)；权限也可能需要 O(N＋去重祖先数)。冷根、冷页及大结果都仍有 I/O。只有经 adapter 证明不会改变错误和缺测语义的摘要才能做进一步剪枝，本轮不额外承诺新的跨格式属性倒排索引。

## 7. 精确版本、删除与权限语义矩阵

| 事件 | 必须保留的行为 | 内容共享／缓存行为 |
|---|---|---|
| 同路径发布 v2 | Latest 新请求选择 v2；显式 v1 仍绑定 v1，不能偷偷升级 | 相同内容可共享，不同版本 provenance 不合并 |
| v2 不命中谓词 | Latest 返回不命中；不搜索 v1 作为替补 | 与共享无关 |
| 删除 v1 | 新请求不能发现／打开 v1；冻结计划后发现删除返回 StalePlan | tombstone 持久保留；共享块仍被 v2 引用时不删除 |
| 删除整路径／目录或 rename | 沿用现有枚举、权限检查及目标冲突规则；旧路径计划失效 | 新绑定重新封印，旧权限不可搬用；rename 不改变字节身份 |
| chmod/chown 或祖先移除搜索权限 | 提交完成后的新发现、execute、注册和新 open 使用新权限 | 内容缓存可保留；授权缓存立即按依赖失效 |
| uid/gid／补充组变化 | 规范化后形成新的授权主体键；不借用另一个主体的成功记录 | 相同内容 ID 不构成访问能力 |
| 已打开普通文件时 unlink | 当前 `op_unlink` 对写会话／普通打开句柄返回 EBUSY；本计划不改成新的 POSIX unlink 方案 | 不利用共享改写该行为 |
| 已打开只读 IPC 的源删除／权限撤销／结果过期 | 保留已打开 IPC 可读和固定属性行为；新 open/access/注册仍重验 | 结果 store 句柄租约与内容块执行租约分别管理 |
| PreparedQuery／注册 ID 存活但尚未打开结果 | ID 不保证长期授权；每次新执行或新 open 检查当前依赖 | 注册 TTL 不是源／块的永久授权或永久 GC pin |
| 删除后用同一 path/version 重建 | 拒绝；不能因内容 hash 相同而绕过 tombstone | 新版本号可引用相同内容 |

V00 已确认历史源权限来自精确版本 inode，祖先搜索权限取当前目录；不得借版本目录改成另一套继承规则。现有 version-path 禁止 chmod/chown 的规则继续保留。错误优先级也以当前 source→授权／重验→封印→时间→marker／目录的测试结果为准，不能在优化中变成静默空结果。

## 8. 不可变共享与有界直接读取

### 8.1 先目录后 payload

先共享确定编码的版本目录页、格式目录和 layout；这与发现成本直接相关。payload 阶段按**原始编码字节块完全相同**去重，沿用已有摄取分块作为首个候选，不要求 HDF5 chunk／Arrow tile／GRIB message 作为统一物理存储块。解码单元与存储去重块是两层概念。

数据块、内容 ID 的 locator、目录页都禁止原地替换。内容 ID 相同的写入需验证类型／长度及内容一致性；测试须能注入摘要冲突并明确失败。格式解析结果只能在解析协议与规则身份一致时复用，科学语义配置、native dtype 等仍属于相应缓存键。

### 8.2 每个版本直接到数据块

```text
namespace + 精确 path/version
  → VersionBinding
  → FileDescriptor / 范围映射根
  → 与 [offset, offset+length) 相交的映射页
  → 内容块 → 裁剪并按原序拼接
```

范围映射中保存有序 `logical_offset, length, content_id, content_offset`。每个版本有完整的逻辑映射根，内部页可共享，但不能是“上一版本＋补丁”。连续相同定位范围可合并，不连续范围仍使用有界多范围请求。

有界保证应以可测条件表达：查找成本取决于本版本映射树高和命中 extent 数，不取决于版本总数 V；设 `h <= max_map_height`、`e <= max_extents_per_request`、`b <= max_bytes_per_request`，所有页／对象读取都受独立预算及 deadline 约束。上限、溢出检查、空区间和短读错误在 V00/V04 冻结，超限报错而不退回整文件读取。首版映射覆盖完整文件，不引入稀疏洞语义。

一个输出范围可能跨多个共享块；批量 locator 和内容读取不能退化为每 extent 一条 SQL。报告实际映射页、locator、数据 SQL 次数和读放大。整个布局根 hash 不能替代对每个冷读块的校验；按块校验避免小读取为计算整文件 hash 拉取全文件。

缓存与租约继续服从公共字节预算、每请求逻辑需求和输出预算、取消隔离。相同块被两个版本引用可以共享基础解码，但只有解码上下文也相同时才能共享解码结果；不能仅用 payload hash 给不同 layout／过滤器返回同一结果。

## 9. 删除、租约与回收

删除先提交可见性撤销与 tombstone，再考虑物理回收；不先删除内容对象。GC 根至少包括当前可见版本、显式保留的历史版本、在途发布根和已准入执行持有的租约。内部旧快照持有引用不等于允许新用户读已删除源。

第一版建议仅实现**停写且无活动读取租约下的显式 mark-and-sweep**，不引入与发布并行的在线引用计数事务。先从权威根遍历、核验引用闭包，生成 dry-run，再处理不可达内容；tombstone 不随内容 GC 清除。中途失败可重跑，不以不完整扫描结果删除对象。待并发提交／租约协议经过验证再单独设计在线 GC。

未完成 GC 前可保留孤儿块作为安全的空间开销，必须报告其数量与字节，不声称共享节省已等于磁盘释放。当前提交根、恢复保留根、业务可查询历史版本是不同集合，不能永久把所有旧根都当 GC 根使删除永不回收。

## 11. 验证和消融

### 11.1 必须覆盖的正确性

- 精确 v1/v2 与 Latest、最新不命中不回退、删除 latest 后的既有行为；同内容不同权限、相同 path/version 不同 namespace。
- 查询在目录选择、授权、目录 cold read、最终准入／发布之间分别插入 publish、chmod、chown、父目录权限修改、rename、删除；包括未命中候选发生变化。
- 内容缓存命中不绕过授权；补充组规范化与 socket/FUSE 相同；`attr_timeout=0` 不凭 TTL 复用授权。根代次证明与 TTL 授权缓存是独立机制。
- 已打开 IPC 保留读取；未打开注册结果和后续 execute 被撤销阻断；普通文件 EBUSY 行为不变。
- 部分对象写入、部分页写入、提交前／后 crash、确认丢失、重启 incarnation、恢复旧数据库；不产生半发布或“复活”的 tombstone。
- 缺块、短读、摘要／协议错误、对象替换、冲突注入；严格模式与新模式的检测边界分别测试，不把直接 SQL 篡改测试混作合法发布。
- 页／树高／候选／extent／字节／输出／deadline 上限；取消一个等待者不影响其他请求；GC 不触及共享或在用对象。

### 11.2 指标必须能证明省掉了什么

增加并分别计时：head 确认、目录页定位／读取／解析、授权、最终准入、依赖重验、格式目录验证、谓词、映射与数据读取。至少记录：

| 类别 | 指标 |
|---|---|
| 目录 | head_control_calls、catalog_page_reads、catalog_page_cache_hits、selected_sources、selected_versions、history_rows_scanned |
| 验证 | proof_reuse、manifest_revalidation_keys/rows/sql、marker_read_rows/sql、artifact_hash_bytes、changed_dependencies、context_retries／failures |
| 权限 | source／ancestor_checks、授权证据复用、依赖失效、deny；按主体区分但不记录敏感身份明文 |
| 存储 | 新增／共享对象数与字节、目录 COW 写入、逻辑／物理字节、孤儿／保留／可回收字节、摄取 hash 时间 |
| 读取 | 映射树高／页数、extent 数、locator／payload SQL、真实读取字节、解码与复制、pin 字节 |

已有 SDK 总 SQL 计数和 wall time 继续保留，避免用 adapter 内部局部计数代替全链路。当前 54.41 ms 阶段减少后，必须检查是否转移成新的 head、权限或 locator SQL，而不是只看旧 counter 归零。

### 11.3 实验约束

1. 首先沿用固定 N=128/K=2/D=4/depth=2 runner、数据、查询和计时边界；**106.811351 ms 为当前固定最好值 A**，同期旧二进制仅作环境对照，不替换 A。同轮测 GRIB 差距，保留所有观测。
2. 逐步消融目录提交／证明复用／共享解析，分别报告发现和取值；V04 再单独观察 payload 去重。不能把多项改动揉成一个无法归因的结果。
3. 新持久协议若必须重摄取，先记录这是迁移而非纯二进制替换；固定逻辑 corpus、源字节、查询 oracle 和 runner，单列发布／索引构建成本与 namespace 差异。未经说明不能宣称严格同一物理数据库的 A/B。
4. N=128、V=1 主要验收发现 SQL 消除；未来多版本实验分别控制 V 和内容重复比例，并测历史随机读、最新查询、发布与 GC。数据管理器／runner 的 V 扩展须另获批准，本轮不新造多文件 runner。
5. 给 FS 对照同等持久索引和预热条件；生命周期实验统计索引构建与维护成本。空间节省、发布节省与查询收益分开，不把去重率等同于 wall-time 改善。
6. 若优化在固定主要指标上差于历史最好值，不保留负优化；先复核测量和同期 GRIB，再按用户既定规则放弃该性能变更。正确性修复及新增版本功能不能伪装成已经通过性能门槛。

2026-10-17 用户再次明确：所有性能优化以**完整查询计时加速**为依据，完整查询明显减慢时适当回退。阶段耗时、调用次数或微基准只用于诊断，不能替代该门禁；没有证明完整收益的实验不作为已接受优化。两轮 V04 根校验／head 热路径改动已按此撤回，保留 V04 r3 功能基线和完整负结果记录。

同日完成获批的 [N=8 单／跨版本完整矩阵试跑](../reports/version-directory-v04-n8-version-matrix-pilot-20261017.md)：192配置／2,880次查询，V8三轮联合门禁仅两项通过，均为两场景GRIB-All对无索引FS-scan。HDF5、FS-index对照及相对V03的版本增长联合门禁未通过；single_unit/HDF5/Latest存在三轮完整绝对收益，另行保留。当前不将V04提升为全格式共同主线，V03保留为查询性能参照，V04保留为内容共享及限定GRIB场景候选；未据此自动推进V05/V06或扩大规模。

随后按用户授权完成[大文件有利场景实验](../reports/version-directory-v04-large-file-upper-20261017.md)：HDF5 约32MiB、GRIB约8MiB及适配原缓存容量的约4MiB补充点，固定N=8/K=2/D=4，V=1/8，共96配置／1,920次完整查询。36项四轮联合门禁均未通过；GRIB 4MiB single_unit/All 对FS-scan合并中位数快1.081倍但仅三轮通过，single_unit/Latest对V03的V8绝对耗时四轮均胜、版本增量联合仅两轮通过，FS-index均更快。保留这些限定收益，不据此切换通用性能主线。实际V8 payload相同内容节省87.5%，单点修改HDF5/GRIB大档节省84.77%/76.45%；主矩阵objects BLOB从V1增至V8仅增2.51%/37.55%，明确不等同数据库物理磁盘压缩率。原配置／许可证摘要及挂载清理复核通过，V05/V06仍待明确后续任务。

## 12. 编码前需要确认的设计点

2026-10-15 用户已确认 D1–D4 推荐以及 D5 具体预算，均冻结于 [V00 契约](../contracts/version-directory-content-sharing-v1.md)。确认设计不等于批准跳过后续阶段验收；V00 当轮未写生产持久化代码：

| 决策（均已确认） | 冻结方案 | 影响 |
|---|---|---|
| D1 写入与提交权威 | 首版一个 namespace 一个受控 owner；验证 head 原子提交，远端 reader 通过 owner | 本地 generation 才能成为有依据的快捷路径；多独立写入进程不在首版支持范围 |
| D2 读与撤销边界 | 精确版本冻结；每次新执行／结果发布／新 open 准入；已打开 IPC 保留原语义 | 避免把旧 snapshot 当永久权限，明确并发排序 |
| D3 持久格式与启用 | 新通用目录／内容／版本封印协议；默认 strict；新模式显式启用并校验 namespace 能力 | 不原地修改 `/5` 等已发布内容，不添加隐式兼容回退；迁移单独 inventory |
| D4 GC | 首版停写、无活动读取租约的显式 mark-and-sweep | 降低跨对象引用计数和 crash 一致性风险；暂不声称在线回收 |
| D5 去重粒度／读取上限 | 先 metadata/layout，再试点 1 MiB 定长编码块；head 4 KiB、页 64 KiB/256 项、树高 8；每请求 1,024 源/65,536 extent/64 MiB 元数据/1 GiB payload；单批 64 范围/8 MiB | 不引入 CDC 或差分链；V01/V04 验证边界、读放大和实际复用率，修改冻结上限需重新评审 |

成功标准是：**能够解释并验证为何一个热目录不再逐源读取 manifest／marker，同时精确版本、删除和权限变化仍在明确的提交／准入边界生效。** 版本间字节共享是后续独立收益，差分压缩不属于本计划。
