# HDF5 cold-path review (2026-10-07)

This review separates first use of the process-local query/fragment cache from a cold disk or cold IoTDB server. The paired GEOS `/T` probe used the same four direct-query cases and exact output checks on both binaries. Three alternating before/after process pairs are retained in [raw profiles](../hdf5-cold-review-results). Every corresponding query had equal row counts and value hashes.

| Proposal | Finding and action |
| --- | --- |
| Asynchronous next-batch prefetch | The provider already batches missing fragments within the current slab, but `get()` waits for each batch. GRIB overlaps independent message decodes through its bounded executor; HDF5 has no equivalent next-slab task/lease boundary. GEOS point/ROI/levels needed only one payload read call in the first pass; prefetch cannot reduce their first result latency. The wider GEOS selection needed three calls, so a streaming consumer may benefit, but needs a bounded, cancellable, request-budgeted next-slab API and a workload that consumes multiple batches. No speculative background reads were added on the short-query path. |
| libdeflate | The installed experiment environment has no libdeflate development library. The existing zlib path enforces a per-decode scratch cap, checks cancellation between blocks, and rejects trailing input. On the first GEOS pass, DEFLATE took 2.45–2.73 ms across all four cases, versus 63–75 ms total; even zero-cost decompression would save under 5% of that summed wall time. A separate optional codec experiment is needed before adding a dependency and preserving the bounded/cancellable contract. |
| Read-scattered/write-sequential unshuffle | Implemented and measured, then reverted. In three paired first-pass runs, total unshuffle time rose from 0.790/0.827/0.929 ms to 1.383/1.191/1.414 ms. Output hashes matched. The original plane-wise loop remains the faster measured implementation for these 52 KiB GEOS chunks. |
| Shared fill fragment | Confirmed and fixed for chunked datasets. A regression fixture with three missing chunks previously made three cache entries and synthesized 48 B; it now makes one version-bound fill entry and synthesizes 16 B. A second query reuses the same entry without payload I/O or another fill. The request still reserves a full native chunk and honors the runtime memory budget. Unallocated contiguous tiles retain separate keys because the final tile can have a shorter length. |

The libdeflate assessment uses its [documented whole-buffer zlib API and per-decompressor allocator](https://github.com/ebiggers/libdeflate/blob/master/libdeflate.h) to identify a possible future implementation, not a measured speedup. A new codec must verify consumed input length and actual output length, retain cancellation behavior, and pass the existing filter-mask/corruption tests.

Validation: the new fill regression failed against the prior implementation (three misses, 48 B fill) and passed after the fix (one miss, 16 B fill). A second regression covers a short unallocated contiguous tail followed by a full tile. All 1,340 unit tests passed after the final changes.
