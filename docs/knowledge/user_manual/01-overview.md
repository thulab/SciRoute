# 概览与基本概念

## 1. 手册概览

### 1.1 适用读者

本手册面向三类用户：

- 文件系统使用者：需要把 IoTDB-FS-C 挂载为目录，并进行常规文件读写。
- 数据分析用户：需要通过查询、检索和扩展路径访问结构化子数据。
- 部署与运维人员：需要配置 IoTDB 连接、构建发布包、执行自检和定位故障。

如果只是第一次试用，建议先阅读第 2 章快速开始；如果要了解系统行为，再阅读第 3 章到第 6 章；如果要使用查询、Web 浏览器或高级扩展访问，从第 7 章开始查阅。

### 1.2 系统能力总览

IoTDB-FS-C 是一个基于 FUSE 的用户态文件系统。用户把它挂载到本地目录后，可以通过常规 POSIX 风格命令创建、读取、覆盖、删除文件和目录。系统把文件元数据、索引和版本信息组织到 IoTDB 中，并在需要时提供查询、历史视图和高级结构化访问能力。

核心能力包括：

- 作为挂载目录使用：通过 `ls`、`cat`、`cp`、`mv`、`rm` 等命令操作文件。
- 元数据管理：维护 inode、路径、大小、时间、版本等信息。
- 最新视图与历史视图：默认面向最新文件版本，同时保留覆盖产生的历史信息。
- 查询与检索：通过自然语言 grep 和跨文件查询定位目标文件或子数据。
- Web 文件管理器：用浏览器查看挂载目录、排序、预览和下载文件。
- 高级扩展访问：通过扩展路径对支持的数据格式读取子数据、裁剪或插值。GRIB 气象数据是当前高级扩展访问的具体案例。

### 1.3 典型使用路径

普通用户的典型路径是：

1. 准备 FUSE、IoTDB 和构建依赖。
2. 构建 `iotdb_fs` 和 `iotdb_fs_web`。
3. 修改 `resources/config.properties` 中的 IoTDB 连接和挂载点。
4. 启动 IoTDB-FS-C 并挂载到 `/mnt/dfs` 或自定义目录。
5. 在挂载目录中读写文件。
6. 使用 grep、Web 管理器或扩展路径完成高级访问。
7. 使用 `fusermount -u` 卸载文件系统。

### 1.4 术语约定

- 挂载点：IoTDB-FS-C 暴露给用户的本地目录，例如 `/mnt/dfs`。
- inode：文件或目录的元数据记录，包含路径、大小、时间、版本等信息。
- 最新视图：默认看到的文件系统视图，只展示每个路径的最新有效版本。
- 历史视图：保留覆盖和版本变化后的历史信息，用于回溯。
- 扩展路径：在文件名后追加查询参数的访问形式，例如 `file?function=read&...`。
- 结构化子数据：从一个大文件中按条件读取的局部数据块或数据场。
- 自然语言 grep：用自然语言描述目标数据，由系统转换为检索计划。

## 3. 文件系统基本概念

### 3.1 整体架构

IoTDB-FS-C 的用户入口是 FUSE 挂载点。用户在挂载目录中执行文件系统操作，FUSE 回调把这些操作转交给项目内部逻辑；系统再把文件内容、元数据、索引和版本信息组织到后端存储和 IoTDB 中。

从用户角度看，最重要的是三层：

- 本地挂载层：提供类似普通目录的访问方式。
- 元数据与索引层：记录文件路径、属性、版本、结构化索引。
- 扩展访问层：对支持的数据格式提供子数据读取、查询和计算式访问。

### 3.2 挂载点与后端存储

挂载点是用户操作的入口，例如 `/mnt/dfs`。配置中的 `mount.point` 是默认挂载点；命令行显式传入挂载点时，以命令行为准。

用户不应绕过 IoTDB-FS-C 直接修改系统内部后端数据。常规读写应通过挂载目录完成，这样元数据、索引和版本信息才能保持一致。

### 3.3 文件、目录与 inode 元数据

每个文件或目录都有对应的 inode 元数据。元数据用于支持：

- `ls -l` 等属性读取。
- 文件大小和时间信息。
- 路径查找。
- 最新版本去重。
- 查询和检索的候选过滤。

可以使用 `getfattr` 查看扩展属性：

```bash
getfattr -d -m - /mnt/dfs/hello.txt
```

### 3.4 最新视图与历史视图

默认视图面向“当前文件系统状态”，即同一路径只展示最新有效版本。文件覆盖写入时，系统会记录新的版本信息，旧版本仍可用于历史管理和跨版本查询。

在演示流程中，普通 `ls -l /mnt/dfs` 用于观察最新视图，`ls -la /mnt/dfs` 可用于查看包含历史信息的视图表现。当前实现会把同一路径的旧版本显示为隐藏文件名，格式类似：

```text
.原文件名_时间戳.扩展名
```

历史版本可读，但不能以写方式打开，也不能 truncate。

### 3.5 普通文件与扩展文件访问

普通文件访问不需要特殊路径：

```bash
cat /mnt/dfs/hello.txt
```

扩展访问会在路径后追加查询参数：

```bash
cat '/mnt/dfs/show.data?function=read&type=binary&offset=0'
```

扩展访问只对已经实现索引和处理逻辑的数据类型有效。当前仓库中的 GRIB 气象数据示例属于高级结构化数据访问案例。

### 3.6 POSIX 兼容范围

IoTDB-FS-C 支持常见文件系统操作，包括：

- `getattr`、`readdir`
- `mkdir`、`rmdir`
- `create`、`open`、`read`、`write`
- `unlink`、`rename`、`truncate`
- `getxattr`、`listxattr`

它面向工程和科研数据管理场景，不应假定所有底层 POSIX 语义都与本地 ext4/xfs 完全一致。遇到依赖锁、稀疏文件、特殊设备文件或高并发细节的程序，应先做环境验证。
