# 多训练实验共享基础数据：实验结果

当前 IoTDB-FS 的跨视图共享和变量投影已经能兑现为更少的读取、解码和缓存副本，但本轮没有证明它比普通 FS 的训练取数更快。普通 FS 的共享读取器也能获得相同基础块的复用收益；IoTDB-FS 额外的查询、授权和结果交付成本仍然占主导。

## 主实验：相同总预算、不同训练视图

使用 Electricity 的原始 Arrow 和 SM128 未压缩派生布局。四个视图为 L/H=64/24、96/24、128/48、192/48，分别投影 64/96/128/64 个通道，最后一个逆序投影。每个视图 24 请求、每请求两个窗口，合计 96 请求、192 个样本，逻辑值数据为 10,567,680 字节。时间重叠场景使用不同 anchor 偏移；负对照使用物理块不重叠的时间区间。

共享总预算 1 GiB；私有缓存每实验 256 MiB，总量相同。三次独立重复，每次一遍应用缓存冷、一遍暖，共 6,912 请求／13,824 样本，全部 Float32 位模式、mask、形状与顺序验证通过。所有非压力冷轮解码数精确匹配独立区间需求 oracle；所有暖轮 payload 读取与解码均为零。没有清理 OS/数据库缓存。

下表为四视图合计的冷轮均值，MB 为十进制。执行耗时包含返回连续训练数组的完整请求路径，初次视图构造与准备另列。

读取字节是应用层请求量，不能等同于物理磁盘 I/O。FS mmap 的页缓存本来就由 OS 共享；FS 缓存记账还包含可能共享同一物理页的 Float32 视图，不能把其数值下降直接解释为实际 RAM 节省。

| 路径与布局 | 缓存 | payload/IPC message 读取 MB | 解码单元数 | 执行时间 s | 缓存记账 MB |
|---|---|---:|---:|---:|---:|
| FS 原始 | 私有 | 97.008 | 4 batches | 0.0987 | 121.242 |
| FS 原始 | 共享 | 24.252 | 1 batch | 0.0403 | 30.310 |
| IoTDB-FS 原始 | 私有 | 23.069 | 1,408 tiles | 3.6926 | 23.362 |
| IoTDB-FS 原始 | 共享 | 12.583 | 768 tiles | 3.6306 | 12.656 |
| FS SM128 | 私有 | 52.466 | 276 blocks | 0.1284 | 65.357 |
| FS SM128 | 共享 | 15.398 | 81 blocks | 0.0551 | 19.181 |
| IoTDB-FS SM128 | 私有 | 52.285 | 276 blocks | 5.7836 | 59.959 |
| IoTDB-FS SM128 | 共享 | 15.345 | 81 blocks | 5.0565 | 17.263 |

原布局 IoTDB-FS 共享减少 **45.5%** 的 payload 和解码，缓存记账减少 **45.8%**。不过执行时间仅减少约 **1.7%**，三轮配对加速范围 0.996–1.038×，不能声称稳定的延迟提升。

SM128 IoTDB-FS 共享减少 **70.7%** 的 payload 和解码，缓存记账减少 **71.2%**。执行均值 5.784→5.057 s，降低约 **12.6%**；三轮配对加速 1.117–1.177×。包含四视图构造与首次准备后，总成本 20.243→19.401 s，配对加速均值只有 **1.044×**。共享方案的四视图准备本身仍需约 **13.731 s**。

FS-shared 同样从 276→81 个 SM128 块，说明此复用机制不专属于数据库。这里 FS 共享读取器是同进程共同 loader，不包含独立训练进程之间的 broker/IPC 服务；它是共享实现的强对照，不能据此声称已覆盖所有多进程部署成本。即使保留各实验私有 FS 缓存，本轮 FS 的取数时间也明显低于生产 typed 路径。

## 负对照与索引边界

时间不重叠时，SM128 私有／共享均解码 **281 块**，IoTDB-FS 均读取 **53.233 MB**；执行均值 5.727／5.767 s。共享 layout 元数据使缓存记账少约 5.755 MB，但 payload 没有复用。它排除了“仅切换共享开关就少读数据”的假象。

覆盖定位与通道投影也通过了机制核验：原布局共享 typed 实际消费 768 个所需 tile，而 FS 读取器消费一个完整大 batch；其读取字节 12.583 MB 少于 FS 的 24.252 MB。这证明当前投影路径有选择性，但 FS 对照解码完整 batch，未实现等价通道 tile 索引，不能把这部分差异全部归因于数据库。单文件、单序列、显式坐标也没有检验跨文件语义过滤的索引收益。

## 缓存压力：能持续兑现，但并非独占

SM128 补充实验配置共享 128 MiB／每实验私有 32 MiB；扩大基准 anchor 到 `[1024,65000)`，每视图 64 请求。四视图合计 256 请求、512 样本、28.180 MB 逻辑值数据；私有唯一需求合计 893 块，共享去重后 266 块。三轮冷／暖共 6,144 请求、12,288 样本，全部正确性验证通过。

| 路径 | 缓存 | 冷轮读取 MB | 暖轮读取 MB | 暖轮解码数 | 暖轮执行 s |
|---|---|---:|---:|---:|---:|
| FS SM128 | 私有 | 179.451 | 163.673 | 861 | 0.3139 |
| FS SM128 | 共享 | 50.566 | 0 | 0 | 0.0929 |
| IoTDB-FS SM128 | 私有 | 177.126 | 156.477 | 826 | 15.4552 |
| IoTDB-FS SM128 | 共享 | 50.391 | 0 | 0 | 12.8106 |

IoTDB-FS 私有缓存暖轮发生 **826 次再解码／驱逐、253 次 payload API 调用**；共享缓存均为零，三轮结果一致。暖轮执行节省 **2.645 s（17.1%）**，配对加速均值 **1.207×**、范围 1.188–1.231×。这证明跨实验共享可以在固定工作负载及缓存压力下持续减少读取和解码，而不只节省第一次加载。

冷轮执行 16.098→14.025 s；计入初次构造和准备后为 30.707→28.298 s，配对加速均值 **1.085×**。FS-shared 同样消除了暖轮读取，其配对加速均值 **3.376×**，绝对执行时间仍明显低于生产 typed 路径。因此该实验仍不支持 IoTDB-FS 的相对 FS 总时间优势。两后端的配置额度与内存记账范围差异见下方适用范围。

更早的 32 MiB 总预算／8 MiB 私有预算探测在 layout 加载处返回 `fragment exceeds runtime memory budget`，没有完成 typed 查询。其日志和未完成结果保留在证据包中，不纳入性能均值。扩大后的预算保持生产内存检查不变。

## 为什么资源收益尚未成为系统优势

四视图的 prepared ID 独立，当前 socket `window_prepare` 为每个视图重新准备 snapshot、coverage index 和 module；共享 runtime 尚未消除这些准备。见 `src/query/frontend/QueryRegistrationSocket.cpp`。训练窗口内容及顺序不同，结果不能作为同一个最终结果复用，授权、规划、IPC、发布和客户端转换仍按请求执行。

主实验所有暖轮都已经零 payload I/O，原布局 IoTDB-FS 共享仍需 3.447 s，SM128 仍需 4.812 s；FS-shared 分别为 0.0218 s、0.0306 s。暖轮差距说明继续减少基础数据读取无法解决当前完整路径的主要成本；这些差值也不能全部称为数据库的固有开销，因为两个前端实现及服务契约不同。

## 复现和适用范围

方法见 [实验设计](../deliverables/arrow-shared-training-views-experiment.md)，主原始汇总位于 `docs/results/arrow-shared-training-views-20260930/main-summary.json`。运行冻结生产二进制 SHA256 `ac32a6b3b6f70ffc0d129268c6914c0bd61e32e70cb22850888e6e0faf63ab33`，未修改生产 C++。

压力汇总为同目录 `pressure-summary.json`。两个成功实验合计 **13,056 请求／26,112 样本**；22 项 Python 测试和 diff 检查通过。核验了全部 **6,528 条 typed 请求**的实际 runtime 缓存额度、条目数与 worker 配置。实验完成后恢复原 mount 配置、关闭 profiling，daemon PID 为 `1001546`。

证据包 `shared-training-evidence-20260930.tar.gz` 包含两组原始结果、profile、执行时 runner、输入清单及失败预算探测，排除了私有配置与 daemon 日志。包大小 2,041,598 字节，SHA256 `327e5413a939e0cad8552012287d2e0ff7d8c6ec24e613d46997fe8e67af99c0`；逐文件清单见 `shared-training-evidence-provenance.json`。

这是训练取数负载回放，没有运行模型优化器；请求串行轮转，不代表并发吞吐、公平性或 DDP 扩展性。typed-private 是四个独立 daemon 生命周期成本之和，重启耗时排除；不是四进程并发 makespan。缓存记账不含全部 prepared context、结果存储与进程 RSS。三轮给出均值、范围和配对比，不作统计显著性宣称。

三轮是同一固定轨迹的计时重复，范围不代表不同随机训练轨迹的变化。两后端仅配置额度相同：typed 还约束 layout、在途和临时内存，FS 主要限制保留的 decoded arrays；不能视作等 RAM 控制。Typed 缓存数值取一遍内请求结束后的最大值，FS 取一遍结束值；压力下不进行同口径的驻留量或峰值比较。
