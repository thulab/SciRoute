# 固定 N512、C128→C512 的暖发现成本诊断

结论：本轮没有复现“C 增长四倍，Td 稳定增长五倍”。原始无探针二进制四轮的 C512/C128 倍率均低于 4，中位 **3.434×**。费用回放仍是主要处理成本；其每条身份的树比较次数及 CPU 成本随规模增加，但不能把这种单位成本增长等同于总 Td 必然超四倍，更不能倒推它就是历史额外约 5% 的唯一原因。本轮只测量与归因，未落地新的性能优化。

## 1. 原表与新测量分别说明什么

用户提供的原始数据为 `1.282→2.526→5.664→23.794 ms`。按历史完整精度，C128→C512 为 `23.794377 / 5.664311 = 4.200754`，除以 C 的四倍增长后为 **1.050188**，而非 1.25。相对四倍线性的差值为约 1.137 ms。

历史三轮端点倍率分别为 **6.355384、4.200754、3.945417**。原数据各 C 独立挂载，发现与取值混合执行，只有每档每轮十条正式记录；其波动及协议不能支持“额外 5% 是稳定算法系数”的判断。历史原始记录、身份与资源摘要已独立核验，全部样本保留；没有把嵌套的原有 profile 时钟相加或把未计时部分当作费用时间。

本轮使用产生原表的同一原始二进制 A：`3d58c7d56740fbb2a2b962e8b3558b5c12ee65703545e93ecb15f69a85d27cb3`。以下为每轮同一次挂载内，两档各 30 条正式发现的中位数，以及同轮 C512/C128 比值：

| 轮次 | C128 Td ms | C512 Td ms | 同轮倍率 | 倍率／4 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 4.462263 | 14.889572 | 3.336776 | 0.834194 |
| 2 | 4.006715 | 15.350060 | 3.831084 | 0.957771 |
| 3 | 3.887840 | 13.726944 | 3.530738 | 0.882684 |
| 4 | 4.606502 | 14.701735 | 3.191518 | 0.797880 |

主统计为四个同轮倍率的中位数：**3.433757×**；每 C 的归一化成本为 **0.858439×**。不使用跨轮绝对中位数之比替代该统计。全部四轮均低于 4；本轮原始二进制没有改动，因此与历史的绝对耗时差异不能称为产品优化收益。

## 2. 实验身份、时钟与边界

复用已封印的 `FM1-hdf5-N512-V1-C128-S0-base-latest` 和 `FM1-hdf5-N512-V1-C512-S0-base-latest`。两档是同一完整 N512 语料、namespace、head、journal 和原生文件位置中的嵌套 scope；P=C、C_versions=C，V1／D4／K2／S0／Latest。不重新发布语料、不重建 FS-index、不新增位置绑定。

四轮产品顺序 AB／BA／BA／AB；每个产品每轮只挂载一次，两个 C 在该 mount 内按预登记顺序交替。每档每轮 5 暖身＋30 正式，总计 **560 条记录（80 暖身、480 正式）、8 次挂载**，全部保留，无按延迟剔除、追加或择优重跑。仅执行发现，不执行 typed value 查询；不能据此声称重新验证完整 T、取值 q 或相对 FS-index 的收益。

A 保留原客户端的两个 Td 外部时钟：请求构造→control call→发现 rows 构造→scope 检查。诊断 B 仅在同源隔离副本的五个文件中加探针，SHA 为 `3fa55b1c012d281a11c3e5a0538520d7c87f82c9d0621e4b65679253e3e488c4`。B 的独占 span 逐条闭合至诊断 root，root 位于原 server_total 内；客户端边界时钟也逐条闭合至 Td。请求 JSON 为 12,684→48,012 字节（3.785 倍）；输入字节增长和 C 增长也不能直接等同。B 四轮总 Td 倍率中位 3.434345×，只作诊断背景，不能以 B/A 当作优化效果或严格的探针开销校准。

原始构建及既有测试收据逐 SHA 核验；A 的“无探针”不意味着替原始收据追认完全干净构建。新增 B 的独立 Release 全量干净构建、编译器和依赖对照通过，96 项专项及 1,782 项全量单元测试无失败或跳过。测量脚本 20 项、独立审计 19 项、费用重放 10 项、分段分析 4 项离线自测通过，实际 C++ 导出与二进制身份往返自检通过。

## 4. 真实费用身份重放：有单位成本增长，但不是第二次全量收费

每个请求的账本在首次 prepared batch 之前，已由 `owner.view()` 产生 **1 个 head 身份、140 个逻辑字节**。本轮导出真实初始 map，再保存四份不可变费用 batch 及五次调用事件。所有正式 B 行均证明：初始 map 与实际 profile 对账；首次 batch 之后，普通 observe／observe_unique 没有新增节点或收费字节；最终账本与真实 batch 并集对账。

身份包含 NUL 和非 UTF-8 版本字节，使用显式 `latin1-bytes` 字节编码，严格恢复原始字节，不按 Unicode 路径重新解释。下列计数来自真实身份，不用 C 个合成键替代：

| 指标 | C128 | C512 | 增长 |
| --- | ---: | ---: | ---: |
| 首次回放访问条目 M | 5,745 | 21,471 | 3.737337 |
| 最终账本节点 U（含初始 head） | 3,068 | 11,248 | 3.666232 |
| 批次新增账本节点 | 3,067 | 11,247 | 3.667101 |
| 访问的身份原始字节 | 1,526,021 | 5,851,570 | 3.834528 |
| 新增节点复制的身份原始字节 | 784,833 | 2,962,070 | 3.774140 |
| 树 less 比较调用 | 90,376 | 396,466 | 4.386850 |
| less 比较的逻辑字节对 | 9,372,097 | 41,203,012 | 4.396349 |
| 对已存在身份的再次观测 | 2,678 | 10,224 | 3.817774 |
| 最终预算逻辑字节 | 2,179,809 | 7,333,193 | 3.364145 |

每次访问的 less 比较由 **15.731→18.465 次**，增加约 **17.4%**；每次 less 比较约检查 **104 个逻辑字节对**，两档接近。因此可见的是长身份被反复比较、访问条目与树深度共同增长，而不是断言身份前缀长度本身增长了四倍。逻辑字节对不是 CPU 指令，生产 `memcmp` 可向量化；比较计数进程与计时进程分开运行。

在完整采集、资源恢复及独立审计通过后，已使用**原始 QueryMetadataBudget.h** 编译独立重放，按实际初始 map 初始化新账本，保留四个 batch 和同一 proof shared_ptr 的重复别名。JSON 解析及不可变 map 构造在时钟外。每档每轮 20 暖身＋100 正式，共 960 条重放记录、800 条正式；八个输入 SHA 实际只有两个独特内容，因此这是**同一真实工作负载对的四轮计时**，不是八种独立工作负载或 800 个独立实验。

| 第一次回放批次 | C128 条目 | C512 条目 | 条目倍率 | 原始代码 CPU 倍率 |
| --- | ---: | ---: | ---: | ---: |
| fee_selection | 1,273 | 4,077 | 3.203 | 3.353 |
| proof_replay | 2,289 | 8,683 | 3.793 | 4.051 |
| fee_manifest | 1,798 | 7,174 | 3.990 | 4.237 |
| fee_catalog | 385 | 1,537 | 3.992 | 4.274 |

原始预算代码五次调用的 CPU 合计增长 **3.949934×**（wall 3.949578×），各轮 CPU 倍率为 **4.0251、3.9100、3.9301、3.9697**。每条访问的 CPU 增长约 **5.69%**。manifest／catalog 分段确有约 4.24／4.27 倍增长，但 selection 只有 3.35 倍，因此不能以其中一段替代总回放或总 Td。

四轮各自 CPU 中位数范围：五次调用合计 C128 **1.236～1.252 ms**，C512 **4.892～5.071 ms**；首次 proof 为 **0.531～0.549→2.145～2.220 ms**。第二次 proof 只有约 **0.94～0.98 μs**，确认命中 memo，没有再次遍历数千条身份。该微秒级时间含固定读钟开销，零条身份访问是更直接的证据。

`std::map::lower_bound`、精确字符串相等检查、max-delta 费用去重、`emplace_hint` 新节点及字符串复制，构成了首次回放的实际工作。**已经去重收费，不等于不同 batch 不再查账**：跨 batch 对已有身份的再次观测仍有 2,678→10,224 次，但这些观测没有把费用值再次提高。构造、真实初始 map seed、账本销毁分别计时，不混入 prepared loop；线上 wall 与离线 CPU 的 allocator／cache／调度条件不同，不能相减当作 off-CPU 时间。

## 5. 能确认与仍不能确认的原因

可以确认，暖发现主要成本仍在本进程的费用账本，不在 SQL 或全候选索引扫描；树查找的单位身份工作量有增长。费用批次访问条目本身仅增长 3.737 倍、初始及其他固定成本存在，足以使总 CPU 和总 Td 的倍率低于 4。仅凭总 Td/C 的比值也不能反推出变量项系数或假设一个固定 F 来证明预设的 1.25。

不能确认历史额外约 5% 的唯一来源。新协议让同一 mount 的两个 scope 交替，只运行发现；历史协议为各 C 独立 mount，并混合发现与取值，运行历史和环境不同。本轮没有尝试从新数据追认旧数据某一次停顿的原因。

事后按预登记的起始 scope 将每轮分成各 15 对样本，A 的八个分层倍率约 **3.108～3.681**，仍全部低于 4；这不替代主统计，也未剔除任何样本。存在与请求位置相关的明显离散，大小 scope 先后顺序的方向会随轮次翻转。源码固定四个 socket worker，但本轮未记录每次执行 TID；线程、分配器、cache 与调度只能列为后续可检验解释，不能被断言为历史超额的根因。

下一步优化优先对准公共预算模块中首次回放的身份表示、树查找和节点／字符串分配，并保留精确路径／版本、逐阶段限额、权限、head gate、失败次序及嵌套 collector 语义。删除第二次 admission 或把不同费用 batch 当作无条件可跳过，不是由本轮证据支持的方案。本轮没有选择并实施新的产品设计。

## 6. 资源、恢复与实验修订

全部实验使用 guest CPU2/3、共享两核 quota、query 叶组 2 GiB；原 DataNode heap15,232 MiB／direct2,176 MiB 另计。独立审计覆盖 3,172 个隔离观测快照、9,513 次 owned 进程观测，正式请求包络内 OOM／配额节流增量为 0。2,648 个周期快照中 2,052 个位于查询跨度，最大间隔 1.0011 s；所选两 guest CPU 的已观测 steal 为 0。其他 30 个 guest CPU 仍有活动，频率不可观测；没有物理宿主 CPU、共享缓存或内存带宽独占的证据。资源包络还包括计时外核验，不能当作纯 Td CPU。

最终额外只读核验确认：DataNode PID **199882**，ASYNC／partial-insert=true；**292 个线程**恢复原 0–31 亲和性及原 cgroup；3 个临时资源组消失，8 个实际嵌套挂载点均卸载，8 个实验 daemon 的进程身份已退出。原配置字节与采集前一致，SHA `f69f408de5c09edabae3a8293cf662327f794b908cbf98d5a02b3878fea154f4`，保留已确认的 1% 磁盘阈值；三份保护文件摘要一致。512 个原生 blob、原 namespace head、journal、FS-index 和位置绑定均通过核验。

预备诊断的二进制身份导出问题在科学查询前修正。随后 `collection-r1` 因错误的“首次批次前账本为空”门禁停止，保存 80 条 query 行，另保留触发门禁的第一个正式请求 profile；服务和资源完整恢复。这些不完整记录未混入本次统计，完整保留。修正为真实初始账本后重新预登记 `collection-r2`，完整采集全部 560 条；未按结果快慢选择重跑。

独立审计另修正了一处离线 schema：严格期望集合补上已存在的 json_parse span；前版及测试记录保留。派生白名单补入线上到重放的输入绑定和修订来源；旧导出脚本及哈希同样保留。这些修订未改变 collection-r2 的产品、runner、计时或统计规则。

Claude Code CLI 按用户要求重试成功，英文 prompt 与原始 3d58 源码核验、完整 review 均保存。采纳其可定位的机制和测量建议；关于 miss、固定项和每候选成本的猜测未替代实际测量。
