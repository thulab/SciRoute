## 已识别的资源语义限制

原 r1 归档内核为 `6.8.0-139-generic`；运行期配置确认为 `cpuset.cpus.partition=isolated`、effective/exclusive CPU 为 2–3、`cpu.max=200000 100000`。Linux 官方文档明确说明 isolated 分区关闭调度器负载均衡：[Linux 6.8 cgroup v2 文档](https://www.kernel.org/doc/html/v6.8/admin-guide/cgroup-v2.html)。

允许使用两个 CPU 不保证实际工作均匀分布。原 r1 的活动包络中 CPU2 有大量用户态 ticks，CPU3 用户态 ticks 为零；低平均核数与显著 CPU 等待压力可以同时出现。关闭自动均衡可能造成栈内竞争，是机制候选；不能据此将全部时钟波动归因于该设置。此次续跑保留原资源协议，避免中途改变对照条件。

同算法 C/B 的完整 R 倍数由旧三轮 0.842986 变为新三轮 1.008518；旧的明显相对优势没有重现。新三轮 C/B 原始完整 T 倍数仍为 1.057021。不能将这些差异解释为几何映射收益，因为两配置在该查询中均零映射查找／构建。

FS-index 自身实现和语料未变：旧九块的完整时间中位数最大／最小为 2.286 倍，新九块仍为 1.512 倍；跨两次十八块为 2.453 倍。这确认测量存在明显运行时波动，但不证明其全部来自外部进程。次要 B/A 六轮完整 R 倍数为 0.960227、原始完整 T 为 0.927634（五轮下降、一轮上升），是后续简化优化可参考的信号，不据此事后改选 B 或自动恢复候选。
