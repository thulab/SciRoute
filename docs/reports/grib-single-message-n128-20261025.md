# GRIB 单 message 直接执行：正确性与 N128 1/2/4 路复跑

2026-10-25。实现、Linux 正确性验证、候选版和同期旧版完整采集、独立复算及服务／资源恢复均已完成。原冻结优化前结果与本轮原始数据保留，不改写、不剔除慢样本。

**局部交接瓶颈已解除，完整查询尚未显示一致提速。** 同期旧版对照的 GRIB 八在途 QPS 变化为 S1 +4.58%、S2 −4.05%、S4 +3.87%；相对冻结历史旧版则为 +2.71%／−11.65%／−5.84%。4 路 cursor 从同期旧版 0.577ms 降至 0.049ms（−91.53%），但局部改善不能替代完整 T 和吞吐的验收。

候选版内部 S4/S1 的同轮配对吞吐变化中位数为 −8.57%，三轮分别 −16.43%／−8.57%／+26.72%，不能据此认定 4 路稳定优于 1 路，也不能用三轮描述性结果宣称统计显著。旧实现即便单 message 命中 native cache 仍跨内部 executor；本次按用户要求直接执行。未修改的 HDF5 2 路跨块 QPS 也相差 +35.53%，跨块差异不能全部归因于 GRIB 改动。

## 实现与语义

- DenseGrid **筛选后恰好一个 message** 时，跳过 GRIB 内部 executor，复用现有同步 `decode_cached_grid`，在公共查询 worker 的 `next()` 内取值／渲染。文件本身可以包含多个 message。
- 多 message 的预取、顺序消费与 permit 不足时的回退保持。没有新增查询内拆分、客户端 worker 或 IoTDB 并行。
- 保留原精确版本与 producer source、逻辑 payload 预留、逐来源费用重放和 runtime 资源控制。同步执行安装 cursor 创建时捕获的 metadata ledger（含空值）及 execution lease，隔离／恢复调用线程额外的 metadata trace、profile 与 storage-read control，保持原内部 worker 的上下文边界。
- 保留入口及 decode 前协作取消、共享 producer survivor、返回状态，以及原标准／未知异常的 code、phase、message、source 翻译。
- 相对冻结优化前，生产差异只有 `src/formats/grib/GribFormatQueryAdapter.cpp`；测试增加五项，另调整三项依赖构造预取的旧测试以继续覆盖真正的 singleflight、多 message 与 permit 回退。

## 冻结实验条件

沿用用户指定飞书 4.3 大表格的已封印独立 N128 组：N=C=128、V1、D4、S0、Latest、K=2、seed20261013。每完整查询交付两个 64×64 Float32 值与 uint8 mask，合计 40960B；GRIB 仍是发现＋两次顺序普通 typed，HDF5 仍是发现＋两项顺序 typed_batch。没有重新发布语料、建立新 case、绑定新位置或重建 FS-index。

S1/S2/S4 只改变公共 worker 和 max batch 为 1/2/4，owner reader pool=4、queue=64、fragment pool=4 固定。单个 asyncio loop 分别保持 single=1、burst8=8 个在途。CPU2/3 exclusive，cpuset partition=root、内部负载均衡开启，父组总 quota 两核，query 叶组 2GiB；DB heap 15232MiB／direct 2176MiB 另计。新旧均为同一编译器、Release 参数及实连依赖库，实际 target 编译／链接命令按 source/build 根路径归一化后相同。

每个实现三轮配置顺序为 1/2/4、2/4/1、4/1/2，每 cell 2 预热＋10 测量波次，另有同期单查询 FS-index。T 从完整查询入口到最终客户端 owned 数组，包含发现、排队、编码及 FUSE/IPC 交付。oracle/profile/资源采样在 T 外，但观测本身仍可能间接影响运行。

本轮先完成候选全部三轮并恢复，再运行旧版全部三轮并恢复。**跨版本是顺序时间块对照，不能视作交错配对 A/B 因果证据。** 历史对照还含跨时段环境漂移；以下变化均为各自三轮汇总中位数相除。
