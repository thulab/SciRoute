# HDF5 S2 内容共享解码缓存 ON/OFF 短探针

状态：已依用户 2026-10-28 的要求回退本次 HDF5 indexed 内容共享实现、范围证明接口及其消融开关；保留此前 payload 块缓存。以下保留当时实现与实验记录，不代表当前运行路径。

日期：2026-10-28。

**原 S2 组没有显示本次内容共享的新增收益。** ON/OFF 首次实际读取量、解码量完全一致，随后均由已有解码缓存覆盖；ON 的两轮温热完整查询中位数分别增加 15.79% 和 12.72%，配对比例中位数增加 **14.25%**。公共 runtime 驻留增加 **832 B**。首次 ON 的墙钟较短，但没有减少读取或解码，不能据此归因为内容共享收益。

本轮是两轮短探针，不声明统计显著性或通用慢化幅度。没有剔除慢样本、补跑或改换命中内容。

## 原始条件与唯一变量

复用此前大 S 探针的 **H-H3-S2**：`FM1-hdf5-N8-V1-C8-S2-base-latest`，N=8、V=1、C=P=Cv=8、D=4、Latest，原六个等值谓词、候选集、发布身份、SQLite 索引和完整 oracle 均不变。每文件大小中位数为 **6,337,470 B**。不重新发布、建索引、绑定位置或清 OS／DataNode 缓存。

S2 放大的是**非命中 dataset**；实际命中仍是两个 64×64 Float32 dataset，各有四个 32×32 chunk，完整 values＋mask 为 **40,960 B**。原八个命中 chunk 的解码内容互不相同，重算数组及 mask SHA 精确匹配封印 oracle；在相同确定可逆解码条件下，没有跨来源相同 encoded chunk 可复用。生产范围身份依赖完整 payload block ID，还可能更保守。

此前块缓存 S2 探针用 native-hdf5，不经过本次 indexed 缓存。本轮 **ON、OFF 都显式使用 `iotdb-indexed` 数据库 payload 路线**，不能将本轮耗时直接与旧 native S2 耗时相减。

两侧使用同一个冻结二进制，唯一功能配置差异为新增 `query.hdf5.content_cache.enabled=false/true`；各挂载仅有自身独立 journal 路径不同。OFF 保留原精确源解码缓存，ON 采用[两层内容共享缓存](../contracts/hdf5-shared-cache.md)。payload 块驻留 8 MiB、请求内／在途复用、layout／索引／候选域／结果引用缓存均保留；`native_cache=true` 在两侧一致，但 indexed 模式不执行 native 文件读取。

单客户端顺序请求，公共查询 worker／Owner reader／sender 容量为 4／4／1，HDF5 read_parallelism=1，公共 runtime 字节预算 2 GiB。固定 CPU 2／3、共享两核配额、query 叶组 2 GiB；DataNode 堆／direct 为 15,232／2,176 MiB。

两轮顺序为 OFF→ON、ON→OFF。每挂载首次 1 次、预热 1 次、测量 3 次，中间插入一组新 FS-index context 的同期五次只读参照。共 **4 个挂载、20 次 IoTDB-FS＋10 次 FS-index 查询**，6 次首次、6 次预热、18 次测量。所有输出和版本 provenance 校验通过。

完整查询 `T=d+q`：t0 从发现前开始，t1 在发现结果交付后，t2 在客户端拥有全部数组及 mask 后；profile、oracle、资源审计在 T 外。首次仅表示新 daemon/context，**不表示冷磁盘或冷 DataNode**。资源 envelope 包含钟外审计，不能冒称纯查询 CPU。

## 完整查询耗时

单位 ms；温热数据为各轮三次测量的 T 中位数。先计算同轮 ON/OFF，再汇总两轮比例。

| 轮次及执行顺序 | 首次 OFF | 首次 ON | 温热 OFF | 温热 ON | 温热 ON 相对 OFF |
|---|---:|---:|---:|---:|---:|
| 0，OFF→ON | 327.441 | 184.009 | 28.383 | 32.864 | +15.79% |
| 1，ON→OFF | 338.350 | 230.283 | 23.828 | 26.858 | +12.72% |

两轮温热配对 ON/OFF 比例中位数为 **1.142526**。完整原始三次测量分别为：

| 轮次 | OFF T，ms | ON T，ms |
|---|---|---|
| 0 | 29.413／28.383／27.275 | 32.864／33.253／31.209 |
| 1 | 21.738／23.828／42.229 | 25.415／26.858／29.890 |

值读取／交付段 q 中位数分别为 23.445→25.304 ms、18.695→20.651 ms；这些阶段中位数不与独立发现中位数相加冒充同一条 T。同期 FS-index 温热 T 中位数为 4.276／2.843 ms，仅作当轮参照，不替代 OFF 基线。

首次 ON 的较短 T 同样保留，但四个首次请求的工作量完全相同。首读传输 wall time 和交付残差存在变化，当前没有单变量证据把它们归为内容复用；不能用首次墙钟缩短抵消温热回退后宣布该组提速。

## 读取、解码与真实复用

以下结果在两轮中完全一致。“后续”包括每挂载预热一次和测量三次，共 16 次 IoTDB-FS 后续查询。

| 每次完整查询的增量 | 首次 OFF | 首次 ON | 后续 OFF | 后续 ON |
|---|---:|---:|---:|---:|
| Payload 实际传输字节，B | 21,477 | 21,477 | 0 | 0 |
| Payload 传输调用 | 2 | 2 | 0 | 0 |
| Store 返回 BLOB 字节，B | 1,624,629 | 1,624,629 | 0 | 0 |
| Store SDK 查询／返回对象 | 2／2 | 2／2 | 0／0 | 0／0 |
| 解码／DEFLATE 次数 | 8／8 | 8／8 | 0／0 | 0／0 |
| 解码产出字节，B | 32,768 | 32,768 | 0 | 0 |
| 新 alias producer＋原内容 producer | 0＋8 | 8＋8 | 0 | 0 |
| 原位提升／内容 ready hit | 0／0 | 8／0 | 0／0 | 0／8 |

Payload 字节来自 runtime 实际 source 调用计数；Store BLOB 字节为底层 SDK 实际返回量，包含其观测到的存储对象，**均不是物理磁盘 I/O**。两者层级不同，不相加。公共 `read_bytes` 同时计入 source 与存储控制费用，也不能作为去重后的物理读取量。

ON 后续每次的八个 ready hit 都来自**相同精确源的重复查询**。OFF 已有八次精确源缓存命中；ON 的 generic runtime hits=16 是八次 alias＋八次内容查找，不能解释成消除了两倍解码。八个不同 chunk 在首次均发生解码，无新增跨来源复用。

因此，本组检验的是“无新增共享机会时的路径和开销”。ON 比原路径多出源别名访问及内容键构造／查找，却没有可消除的 payload／解码工作；短探针观察到的温热 T 上升与该方向一致，但不足以将全部毫秒差值唯一归因于缓存查找。

## 驻留与回收观测

公共 runtime gauge 在同一配置的所有十次查询中一致：

| 查询结束后的 gauge，B | OFF | ON | ON−OFF |
|---|---:|---:|---:|
| cache_owned：解码／别名及费用 trace | 49,648 | 50,480 | +832 |
| temporary：含原块复用生产者保守预约 | 6,498,516 | 6,498,516 | 0 |
| live | 6,548,164 | 6,548,996 | +832 |
| pinned／inflight | 0／0 | 0／0 | 0 |
| runtime 生命周期峰值 peak | 7,628,976 | 7,629,808 | +832 |

cache_owned 增加 1.68%，live 增加约 0.013%。temporary 包含跨请求块驻留保留的原生产者预约，不能当成实际解码缓存数据大小，也不是进程 RSS。

既有候选域公共热池另有相同的辅助驻留增长：每挂载从 **1,383,482→1,659,946→1,936,410→2,212,874→2,489,338 B**，ON/OFF 逐次完全一致，增量记在 auxiliary 指标。不能把全部缓存驻留笼统说成恒定，也不能把这项共同增长归入新增内容缓存。四个挂载均无 runtime eviction／redecode／wait，热池无压力回收。20 次 IoTDB-FS 查询的资源 envelope 内 parent throttled_usec 增量均为零。

结论限于本组：没有新增读取／解码收益，新增驻留很小，而温热 T 有回退。不据此回退内容共享的全部功能或宣称它能解决 S 增长成本。要证明共享收益，需要另行确认具有相同已证 payload 内容的跨来源访问；本轮没有替换原 S2 查询或关闭上层缓存制造机会。
