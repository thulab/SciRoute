# GEOS/HDF5 累计修复复验

> 文档整理：标为“服务器归档”的引用按本次清单不再作为 Git 文档保留，查验路径见 [文档归档说明](../README.md#服务器归档)。

2026-10-10。本轮从精确 `0a62f6e4835c556cbba9dec0a7a6668cb6d412fb` 独立构建 Release，与当前未提交生产修改交错运行相同 GEOS 请求集合。**修复的查询收益可以叠加：每版本 144 请求累计客户端耗时 14.568→4.870 s，下降 66.6%；控制请求元数据 SQL 3,093→585，减少 81.1%。** 完整发布另测为 133.167 s，与历史 136.751 s 仍处于相近量级，不能把查询收益解释为摄取提速。

## 基线与复验边界

20261007 历史运行没有冻结 daemon SHA，不等同于指定 commit。本轮使用只读 `git archive` 导出 exact commit，再用同一 GCC、Release、Arrow 21.0.0、HDF5 1.14.6、IoTDB SDK 编译；未切换工作目录或修改 git 状态。baseline 171 项生产文件与导出清单一致，当前 175 项与上一轮服务器／本地 SHA 清单一致。正常生产 build、既有挂载和原始版本保持原样。

- 精确 commit 对照 daemon：`7e64efeaa1ae137f266aa8ac663c0b74af54ea8159ae06afb148cdf0c3fbcb5c`。
- 当前 daemon：`5b693418506d5fabbdf92ed86c4b6a16eb851a31ef8c50c5fc533cd0dcd281c7`，即 `0a62f6e` 加当前未提交修复。
- 查询使用 `geostime20261007` 中原 16 个路径、精确版本，以及原 `/T`、`standard_name=air_temperature`、UTC 时点语义。未重摄取或替换查询源。发布复验在查询完成之后写新前缀，避免写入干扰计时和改变旧版全目录扫描范围。
- N=1/4/8/16，每版本三轮独立挂载；版本顺序 old/new、new/old、old/new，候选顺序正向／反向／正向。每挂载 hit/miss 各五次，首次再查询一次仅属性并执行一次单点 typed；每版本原样保留 132 目录＋12 typed＝144 请求，合计 288。
- 主实验 `attr_timeout=0,entry_timeout=0`，256 MiB decoded cache、65,536 entries、HDF5 读取并行度 1，raw cache／full-prefetch 阈值 1 B。不清除 OS／IoTDB 缓存。一次公共 FS 索引构建和 oracle 验证在计时外，原生 FS 扫描逐请求另计时。
- 原顺序为首次 hit→miss→全属性→首次 typed→后续 hit/miss。时间暖态取 repeat=1–4，12 样本；仅属性每版本仅 3 样本。最新首次全属性已有目标文件一个解析缓存命中，其余候选未命中；N=1 全部命中。不能称作全冷或全热属性发现。首次 typed 每挂载冷 layout，零 TTL 权限预填禁用。
- 另有 TTL=1 暖态 GRIB/HDF5 控制组，三对独立挂载、每格式每版本 15 个计时样本，另含预热；总 72 请求，不混入原 144 请求总计。所有样本保留，未剔除首次 Python/Arrow 惰性初始化成本。

不同修复消除不同层次的重复工作：catalog SQL 下推减少无关版本扫描；source/parent 权限证据贯通减少授权补读；manifest 重验由逐源变为有界批量；两个 COUNT 与属性筛选由逐源变为跨源批量；marker 和 OBJECT 再分别合批；验证后的精确版本目录解析结果跨请求复用。它们在最新版本同时生效，仍保留逐请求授权、新鲜度、请求预算、schema 与实际 COUNT 检查。

权限缓存预填受 TTL 控制：主实验 TTL=0 不产生此项收益。它与公共 catalog/权限合并在另一个 TTL=1 暖态边界共同验证，不能把该数字替换零 TTL 首次 typed。

| TTL=1 暖态 typed | 服务端 exact→当前，ms | 注册＋stat＋完整 IPC 读取 exact→当前，ms | 元数据 SQL |
| --- | --- | --- | --- |
| GRIB | 29.107 → 8.656 | 41.663 → 9.688 | 4 → 1 |
| HDF5 | 26.654 → 4.638 | 38.415 → 5.636 | 4 → 1 |

两个格式的完整 IPC SHA-256／字节数前后相同；HDF5 5,752 B、GRIB 67,648 B。GRIB 同入口也受益，说明这部分主要是公共系统调用减少。控制读取器按字节消费 IPC，与主实验通过 Arrow 复制 Float32 值的读取器不同。

主实验 TTL=0 首次 HDF5 typed 客户端 96.901→69.141 ms，服务端 38.573→23.668 ms；注册元数据 4→1，冷 layout 均3次、payload均1次，IPC均5,752 B。完整消费仍受零 TTL FUSE 授权和冷 layout 影响，因此没有降至 TTL=1 暖态的5–6 ms。

## 普通 FS 对照与剩余成本

| N | 当前时间命中发现，ms | FS 原生逐文件验证扫描，ms | FS 内存索引命中，ms |
| ---: | ---: | ---: | ---: |
| 1 | 36.740 | 3.670 | 0.055 |
| 4 | 39.101 | 12.123 | 0.048 |
| 8 | 40.306 | 23.714 | 0.043 |
| 16 | 41.533 | 46.593 | 0.050 |

N=16 本轮 IoTDB-FS 时间发现略快于原生逐文件扫描；N≤8 仍较慢，预建内存 FS 索引也仍显著更快。这里只有16个公开时次、单客户端，且系统接口／预处理不同，不能据此宣称普遍胜过 FS。FS 索引计时仅内存查找与身份检查，不含 JSON 加载或温度取值。

N=16 首次仅属性阶段 p50：目录准备21.890 ms（其中缺失对象读取／解析15.642 ms），manifest重验5.600 ms，完整性 COUNT70.150 ms，属性筛选23.722 ms。阶段为嵌套且中位数不可相加。对象复用收益已经兑现，当前余量主要在 COUNT和属性SQL；完整发布仍是 raw 数据到首次可用的最大绝对成本。

## 完整发布与新版本验收

查询之后，使用未修改 `geos_pilot.py`、同16原件／顺序、相同数据库与配置，在新前缀重新 `shutil.copyfile` 到挂载。每文件计时包含暂存／close摄取／payload写入／inventory／layout、catalog、时间索引构建和发布；来源SHA、mount、mkdir、stat、后续发现和查询不计入。原件在计时前读完SHA，未清缓存，不是冷磁盘摄取。

| 发布指标 | 历史20261007 | 上次b54c0dba复验 | 本轮当前 |
| --- | ---: | ---: | ---: |
| 16文件发布耗时之和，s | 136.751 | 147.763 | 133.167 |
| 文件／原件字节 | 16 / 7,142,773,610 | 相同 | 相同 |
| 单文件p50，s | 8.271 | 9.016 | 8.453 |

本轮较历史 -2.62%，只有单轮历史比较，未交错执行旧／新发布，不能归因于代码提速或证明发布回归修复。近期修改主要针对查询；它们没有消除逐块payload与manifest写入，因此不能预期约百秒发布成本随毫秒查询成本同比下降。

发布后目录发现单独耗时 154.125 ms、8条完整元数据 SQL，返回16个新精确版本；与历史约699 ms／115条、上次约868 ms／114条相比明显改善，但该验证不在发布计时内。发布 driver 使用 subtree 发现，完整8条=目录内部7条＋1条祖先批量授权；主查询矩阵使用已知 exact 路径，祖先与初始catalog合并，因此为7条。该差异不是新增逐源读取。

16原件SHA／大小／顺序匹配历史；全部新发布文件大小正确，16个layout `/5` digest与对应旧版本相同。每文件单点、ROI、多chunk ROI、多个气压层，共64/64查询的Float32行数及SHA与原生H5Dread一致。所有临时mount卸载，原16版本保持，新发布前缀保留供复验。
