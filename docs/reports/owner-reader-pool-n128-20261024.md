## 路径与解释边界

服务器根目录：`/data_01/zzy/iotdb-fs-exp/IoTDB-FS-C/experiments/cross_version/work/owner-reader-pool-n128-20261024/`；正式采集为 `collection-r1/`。源码、条件、历史参照、补充测试、原始查询、资源序列、启动及恢复收据保存在该目录。私有配置、原配置备份及私有诊断留服务器。

4.3 的 N 表示候选语料规模，K 始终为 2。GRIB 客户端两个取值请求串行；owner 一次 `get_objects()` 批量读取仍占一个 lease，不自动拆成多路 SQL。原生 field cache 命中可跳过 encoded message 与 payload 对象读取。HDF5 本组 payload 经受管 FS 完整文件读取，不经过 owner payload reader pool。必须结合实测 `version_store_*` 判断本组是否实际触及 pool，不能把先前对象并发探针的加速倍数套用到完整查询。

`Owner::view/admit` 的正常热路径检查内存 head；逻辑 `head_control_calls` 不是 SQL 计数。真正的 `read_head()` 仍在串行控制通路，主要用于恢复、初始化和发布确认。完整查询还保留准入、身份校验、费用/预算处理、编码、IPC 和 owned 数组交付；不能把 q 称为纯原生解码时间。
