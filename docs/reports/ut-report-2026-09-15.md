## 已修复的源代码缺陷

此前四个失败并非环境或随机调度造成。第一轮补充了原有测试缺少的“裁剪后再插值”
和“区域经度越界”数值断言，暴露了现存缺陷。源代码修复后，四个原用例均通过；
没有禁用测试或改用错误的数值作为预期。

### 裁剪后插值使用全场范围

用例：`GribRegularGrid.BilinearResamplingUsesSelectedCropDomain`，GRIB1/GRIB2 均已通过。

4×3 网格取值为：

```text
  0  10  20  30    latitude=2
100 110 120 130    latitude=1
200 210 220 230    latitude=0
longitude: 0 1 2 3
```

选择纬度 2..1、经度 1..2，输出 2×2：预期 `{10, 20, 110, 120}`，
修复前实际 `{0, 30, 200, 230}`。`decode_crop_and_bilinear_resample` 计算了裁剪索引，
但输出经纬度范围仍来自原始全场。

修复：由实际裁剪窗口计算插值网格的起点和跨度；无法计算裁剪窗口时返回失败。
新增指定分辨率、网格坐标取整、纬度升序输入、单列，以及服务层单行/单列裁剪后插值
回归，检查数值和虚拟文件大小一致性。普通全场插值仍由原用例验证。

### 区域经度按区域宽度循环

用例：`GribRegularGrid.RegionalLongitudeOutsideGridDoesNotWrapByRegionWidth`，
GRIB1/GRIB2 均已通过。

对于同一经度 0..3 的区域网格，请求经度 0..10 覆盖整个网格。
修复前 `normalize_lon` 以区域宽度 3 度循环，经度 10 被映射为 1，导致仅返回前两列。

修复：经度按 360° 等价换算到网格附近，再将区域外坐标截到实际网格边界，保留该请求
应覆盖的全部四列。换算使用余数运算，避免大经度输入反复循环。
新增负经度、超过 360° 的等价坐标、区域两侧越界、接近 360° 的网格以及服务层回归。
非有限裁剪坐标返回失败；网格索引在转换为整数前截断。

### 空消息导致 ecCodes 崩溃及缓存污染

修复前，当前 ecCodes 2.44.0 下调用 `get_values_count_from_message_bytes({})` 会收到
SIGSEGV（退出码 139）。空向量地址及长度 0 未经检查即传入 ecCodes；读取回调返回
成功但内容为空时同样存在风险，且空结果可能进入缓存。

修复：两个 ecCodes 消息句柄入口拒绝空指针或零长度；消息读取缓存拒绝空向量。
新增空消息计数、裁剪、解码、插值及服务层失败返回测试，并验证同一缓存键随后读取
有效消息能够成功恢复。这些回归均计入最终 591 项 UT 和 10 轮 Sanitizer 检查。

只运行原来的四个失败实例（现均通过）：

```bash
build-ut/bin/unit_tests \
  --gtest_filter='*BilinearResamplingUsesSelectedCropDomain*:*RegionalLongitudeOutsideGridDoesNotWrapByRegionWidth*'
```

## 100% 行覆盖率的可行性

当前统计范围内还有 **157 行未覆盖**。继续增加真实行为测试和故障注入能够提升覆盖率，
但保持现有结构、仅添加测试无法保证达到 100%，因为其中包含正常公开调用无法触达的
防御路径。精确达到 100% 需要先处理这些路径的可测试性和重复检查；不能据此承诺
整个仓库达到 100%。

| 实现 | 未覆盖行数 | 主要后续工作 |
| --- | ---: | --- |
| `gribUtils.cpp` | 60 | 验证 ecCodes 失败与回退；核查重复检查及不适用于当前 sample 的字段路径 |
| `GribFileWriter.cpp` | 25 | 注入读取、刷新、关闭、重命名失败，验证返回状态及临时文件清理 |
| `GribWriteStreamer.cpp` | 20 | 注入句柄和元数据提取失败；核查状态约束下不可达的重复清理 |
| `GribExtensionService.cpp` | 10 | 核查查询参数、内部解析失败和底层错误传播 |
| 其余业务实现与头文件 | 42 | 缓存淘汰后更新、异常及溢出边界、模板实例和重复校验 |
| 合计 | 157 | |

有明确证据的限制包括：

- `gribUtils.cpp:526` 的无效窗口返回在索引已截到有效范围、闭区间宽高至少为 1 后
  不可达；另有缓存非空检查及私有函数未使用的通用分支。该文件的 60 个未覆盖行中，
  53 行需要受控 ecCodes 失败或特殊消息 fixture，4 行按当前公开调用契约不可达。
- `MetadataSchemaCapability.cpp:107–108` 再次处理表名校验失败，但调用方此前已使用
  同一校验规则拒绝非法表名；`117–118` 的 unsupported 分支在当前传参下也不可达。
- `MetadataCache.cpp:134` 是 `size_t` 加法饱和保护，通过实际分配超大字符串触发既不
  稳定也不适合 UT。若需要直接验证，应将预算运算提取为可测试的纯函数。
- `MetadataCache.cpp:144–145` 的错误结果估算分支不可达，唯一调用者已提前拒绝失败结果。

还有一些可以直接补测的路径，例如 `InodeCache.cpp:204–209`：容量设为 1 并保留一个
脏条目，随后更新数据库中的另一个干净条目，会使刚加载的条目被淘汰，触发更新时重新
插入，无需依赖线程竞态。其他入口包括 `std::map` 配置中的 `grib.enabled`、合法 JSON
经 `to_xattrs_json` 投影，以及配置重载失败的具体错误信息。

此外，少数未覆盖行是编译器标记的闭合大括号或异常清理路径，需要核对 gcov 基本块，
不能直接将其当作遗漏的业务用例。例如 `gribUtils.cpp:865` 的正常返回行已经覆盖。

后续宜先补可达错误路径，再针对需要变更的接口或纯函数进行设计确认；对经证明不可达
的冗余检查，按代码质量要求审查整理。保持真实的覆盖率统计，不通过排除源文件、
修改断言或删除必要的错误处理来达成数字目标。最终仍需通过完整 UT 和 Sanitizer。
100% 行覆盖率本身也不代表所有分支、输入组合或业务行为均已验证。
