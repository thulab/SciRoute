# V04 GRIB 内容共享解码缓存修复

日期：2026-10-18。承接 [GRIB 尺寸与缓存诊断](version-directory-v04-grib-size-diagnosis-20261018.md)，修复同一字段反复解码、相同编码内容跨版本不能复用的问题。最终保留与否以完整查询 A/B 为依据；适配器计数用于解释机制。

## 实现与边界

用户已确认以下设计：同 namespace 内按实际读取的 message 字节 SHA-256 共享 canonical Float64 字段，精确源独立保留身份与计费，采用有界两队列与 singleflight，不改持久格式。

- 内容键包括 `grib-native-f64/2`、namespace、message 编码长度与实际字节 SHA-256；不以 layout 身份或版本相似度代替内容校验。
- 源 alias 包含 namespace、path/version、revision、payload/layout size 和 message offset/length。首次绑定必须成功读取编码 message；其他版本的命中不能绕过新源读取失败。
- 原生值和网格几何共享；dtype、crop、interpolation、provenance 和版本结果在当前源单独生成，不折叠历史输出。
- alias 各持有本源稳定费用轨迹。每次消费仍预留本源逻辑 message 并回放本源费用；共享字段不持有首来源的请求 ledger。重新解码已淘汰字段时隔离物理操作轨迹，避免重复收费。
- 相同内容并发解码合并。失败不负缓存，等待者以自己的 producer 重试并归属错误；pending 和 promise 异常路径清理管理结构。
- 首次字段进入 probation FIFO；再次使用或 ghost 命中进入 protected LRU。根据 probation 字节／数量的四分之一阈值选择淘汰队列。alias、ghost 各至多 256 项。
- 保持原生字段保留预算 **64 MiB、最多 16 字段**，字段、alias 费用、ghost、pending 管理共同计入；pending 入队前预留，不能腾出预算时旁路，超大字段不常驻。这不是全部临时解码、输出或 RSS 的上限。
- 编码 fragment 首次加载时计算摘要，runtime 预留计入摘要大小；暖 alias 命中不重新 hash。native 计数只在 DenseGrid 路径启用，MessageRows/BinaryView 不新增这部分计数管理。

没有更改持久格式、客户端协议、精度、账号或许可证。源码与契约在本地及服务器交付；旧 V04 r3 二进制、冻结源码、前缀和历史负结果保留。

## 回归与构建绑定

最终构建通过 **432 项相关测试，0 失败**，其中 57 项为 GRIB Adapter 测试，包含新增 9 项。新增用例覆盖跨路径／版本／revision 内容复用、F32/F64/crop、不同内容和 namespace、独立计费、读取失败、8 源并发、两队列冷扫描保护、300 版本 alias 边界与失败重试。

## 完整查询方法

复用原服务、原许可证及既有 V04 namespace，不重新摄取。N=8、K=2、D=4；4/8 MiB 两档、identical/single_unit 两种变化、V=1/8、Latest/All、old/new，共 16 个配对单元。4 个时间 campaign，每个配置 5 次，共 640 次；每个 campaign 的首请求单列，其余 4 次组成暖观测。组次轮转、old/new 顺序交替，Latest/All 顺序按 campaign 交替。

完整时钟沿用冻结 `n8_matrix.iotdb_query`，包括发现、typed 查询、IPC 和客户端拥有的输出拷贝。profile 等待及独立 value/mask SHA oracle 在时钟外；挂载／owner 恢复独立列出。没有改查询条件、输出、传输边界或 oracle。

每个 arm 使用原 owner journal 的独立副本；每次卸载后检查原 journal、副本 journal 和 head 未变。原服务在已有控制窗口临时切换 SYNC，finally 恢复原配置；不启动独立数据库、不获取新证书。两次导入预检错误发生于数据库操作前，均为 0 查询并保留记录；正式 A/B 只有一轮 controller，没有失败后选择性重跑。

四轮属于时间重复，不是独立语料重复；每单元合并的 16 个暖样本仅作描述统计，不当作 16 个独立实验。各阶段 p50 不能相加解释总时间。

## 机制解释与限制

独立科学文件审计确认：V=8 All 返回 16 个源字段，但完整编码 message 的唯一 SHA 数为 identical 的 **2**、single_unit 的 **6**。8 MiB 档这六个不同字段的值与坐标合计 49,939,248 B（47.626 MiB），去重后可落入原预算；不是让约 127 MiB 的真正不同字段同时常驻。4 MiB 档分别为 8,328,976／24,986,928 B。

主 A/B 同时引入内容复用与两队列，不能分离两队列的独立端到端贡献；热点保护由真实 Adapter 回归验证。旧正式 A/B 二进制没有新增 native 计数，相关旧计数记为不可用，不能记零。此前诊断的旧加载行为是另一份封存证据。

本修复不消除每版本结果输出、IPC 和内存拷贝。命中 message 和返回点数变大时，冷解码及完整输出仍可变慢；冷 ROI 仍需解码完整命中 message。超过预算的不同内容仍可能重新解码。没有在本轮重跑 FS/V03/HDF5，也没有重新裁决 V04 相对强 FS 基线的开发主线门禁。
