# 专利名称：

一种基于时序数据库的标准文件系统读写及优化方法

# 摘要

本发明提供一种基于时序数据库的标准文件系统读写及优化方法。

所述方法以时序数据库作为统一持久化后端，通过用户态文件系统将数据库中的目录、文件、元数据和对象内容暴露为标准文件系统。所述方法包括：在时序数据库中建立用于承载文件系统对象的核心表，以逻辑路径、父目录、文件名、权限、用户、组、大小、时间属性和对象内容字段描述目录或文件；通过 FUSE 层将 `getattr`、`readdir`、`mkdir`、`create`、`open`、`read`、`write`、`release`、`truncate`、`rename`、`unlink` 和 `rmdir` 等标准文件系统操作映射为时序数据库查询、插入、更新和对象字段读写；在写入过程中按文件偏移将对象内容分块写入数据库对象字段，并在关闭时写入结束标记和最终大小；在读取过程中按偏移调用对象字段局部读取能力返回目标字节区间；在覆盖写场景中生成新的时间版本并将历史版本以隐藏文件形式暴露；通过会话池、打开文件上下文、inode 写回缓存、目录子项缓存、原始文件缓存和读块缓存降低数据库连接、元数据查询和对象读取开销。

通过本发明，能够将标准文件系统的目录和文件语义建立在时序数据库之上，使上层应用无需直接感知数据库即可完成普通文件读写；同时通过对象偏移读写、延迟刷库、版本化覆盖写和多级缓存优化，提高基于数据库后端的文件系统在大文件、频繁目录操作和重复读取场景下的性能与可靠性。

# 技术领域

本发明涉及时序数据库存储技术、用户态文件系统技术、对象化文件读写技术以及文件系统缓存优化技术，尤其涉及一种以时序数据库为后端实现标准文件系统目录、文件、读写、覆盖、重命名、删除和性能优化的方法。

# 技术背景：

传统文件系统通常直接管理本地磁盘或分布式存储中的目录项、inode 和数据块，能够向上层应用提供成熟的 POSIX 文件访问接口。但在需要统一利用数据库能力进行数据持久化、审计、查询、版本管理和集中运维的场景中，传统文件系统与数据库系统往往相互割裂。业务系统若希望同时获得文件系统接口和数据库后端的统一管理能力，通常需要在文件系统之外额外维护元数据表、对象存储路径和同步任务。

现有技术普遍存在以下不足：（1）标准文件接口与数据库存储接口割裂，应用程序若直接访问数据库则需要改造为数据库客户端，若继续访问文件系统则难以利用数据库统一管理能力；（2）元数据和对象内容分离管理，目录项、文件属性、对象内容和版本信息之间需要额外维护一致性；（3）大文件写入常采用整文件写入或整对象覆盖方式，单次请求体积大，失败恢复和局部更新成本高；（4）数据库后端文件系统在频繁 `getattr`、`readdir`、`open`、`read` 等操作下容易产生大量查询和连接开销；（5）覆盖写通常直接破坏旧内容，若需要历史回溯、审计或误写恢复，需要额外引入备份机制。

为此，需要一种基于时序数据库的标准文件系统读写及优化方法，既能保持上层应用对目录和文件的普通访问方式，又能将文件系统元数据和对象内容统一纳入时序数据库管理，并针对数据库后端的读写路径进行系统性优化。

# 发明内容：

本发明提供一种克服上述问题或者至少部分地解决上述问题的基于时序数据库的标准文件系统读写及优化方法，以提高数据库后端文件系统的兼容性、读写效率、版本安全性和运维一致性。

本发明的第一方面，提供了一种基于时序数据库的标准文件系统读写及优化方法，包括：

（1）标准文件系统对象建模：在时序数据库中建立核心表，至少包含时间主键、逻辑路径标签、父目录标签、文件名、目录标志、文件大小、权限位、用户标识、组标识、链接数、创建时间、修改时间、访问时间和对象内容字段。其中，逻辑路径用于表示用户可见文件路径，父目录用于支持目录遍历，对象内容字段用于保存文件原始字节，时间主键用于区分对象记录和文件版本。

（2）标准文件系统操作映射：通过 FUSE 用户态文件系统接收上层应用对挂载目录执行的标准文件系统调用，并将属性读取、目录遍历、目录创建、文件创建、文件打开、文件读取、文件写入、文件关闭、截断、重命名、删除文件和删除目录等操作转换为对核心表和对象内容字段的访问。由此，上层程序仍以普通文件接口工作，底层由时序数据库完成持久化。

（3）对象内容按偏移读写：写入时，系统根据文件偏移、字节内容、结束标志和最终大小构造对象写入请求，将文件内容以块形式写入对象字段；读取时，系统根据用户请求的偏移和长度调用 `READ_OBJECT(data, off, len)` 或等价局部读取接口，仅返回目标字节区间；关闭文件时，系统刷新待写入块、更新最终大小和修改时间，并写入结束标记。

（4）覆盖写版本化机制：当用户以写模式打开已有文件时，系统不直接破坏当前记录，而是基于逻辑路径生成新的时间版本，后续写入落到新版本对象内容中。目录遍历时，最新版本以普通文件名展示，历史版本以带时间戳的隐藏文件名展示。该机制作为标准写入安全优化，使覆盖写具备历史可读、审计和误写恢复能力。

（5）连接与上下文优化：系统建立时序数据库会话池，并通过租约对象管理会话借用和归还；每个打开文件对应一个打开文件上下文，集中保存文件版本时间、路径、当前长度、待读写块、读缓存、写入状态和关闭收尾信息，从而减少跨操作状态重复查询和连接建立开销。

（6）元数据与内容缓存优化：系统维护 inode 写回缓存、目录子项缓存、原始文件缓存和打开上下文读块缓存。inode 写回缓存用于合并属性更新并按周期刷库；目录子项缓存用于加速目录遍历；原始文件缓存用于命中小文件或整文件重复读取；打开上下文读块缓存用于优化顺序读取和局部重复读取。各缓存以路径和时间版本作为关键维度，避免不同版本内容混淆。

通过上述方法，本发明能够在时序数据库之上实现标准文件系统语义，降低数据库后端文件系统的连接开销、元数据查询开销和对象读取开销；能够支持对象内容局部读写，避免整文件传输；能够通过覆盖写版本化机制提升写入安全性和历史可追溯性。

# 具体实施方法

下面结合附图和实施例，对本发明的具体实施方式作进一步详细描述。所述实施例用于解释本发明，而不是对本发明的限定。

图1 为本发明实施例一种基于时序数据库的标准文件系统读写及优化方法的总体架构图。如图1所示，该系统包括客户端应用、FUSE 挂载点、文件系统核心进程、时序数据库连接模块、时序数据库、打开文件上下文管理模块、元数据缓存模块和对象内容缓存模块。客户端应用包括命令行工具、脚本程序和普通业务程序。客户端对挂载点执行标准文件系统操作，FUSE 文件系统核心进程接收操作后，将其转换为对时序数据库核心表和对象字段的查询、插入、更新或局部读写。

在一种实施方式中，系统使用 Apache IoTDB 作为时序数据库，核心表名为 `inode`，数据库名可配置。系统启动时读取配置文件，初始化日志，建立时序数据库会话池，自动创建数据库和核心表，并在根目录不存在时创建根目录记录。核心表至少包括 `time`、`path`、`parent`、`name`、`is_dir`、`size`、`mode`、`uid`、`gid`、`nlink`、`ctime`、`mtime`、`atime` 和 `data` 等字段。其中，`data` 为对象内容字段，支持按照偏移写入和读取文件字节。

图2 为本发明实施例的标准文件系统操作映射流程图。如图2所示，当系统接收到 `getattr` 调用时，根据路径查询对应 inode 记录并返回文件类型、大小、权限和时间属性；当系统接收到 `readdir` 调用时，根据父目录字段查询子项并组织目录列表；当系统接收到 `mkdir` 或 `create` 调用时，在核心表中插入目录或文件记录；当系统接收到 `open` 调用时，构造打开文件上下文；当系统接收到 `read` 调用时，根据上下文中的版本时间、路径、偏移和长度读取对象内容；当系统接收到 `write` 调用时，将字节块暂存或写入对象字段；当系统接收到 `release` 调用时，刷新待写入块、更新最终大小和时间属性；当系统接收到 `rename` 调用时，更新目标记录的路径和父目录，若目标为目录则递归更新子路径；当系统接收到 `unlink` 或 `rmdir` 调用时，按文件或目录规则删除对应记录。

图3 为本发明实施例的对象内容按偏移写入、读取和关闭封口流程图。如图3所示，写入请求到达后，系统首先判断写入偏移与当前文件长度的关系。对于顺序追加写入，系统将对象块加入待批量写入队列，并在达到阈值或关闭文件时写入数据库对象字段；对于非顺序写入，系统按照请求偏移将对象块写入对应位置，并更新上下文中的文件长度和修改时间。每个对象写入请求包含偏移、字节内容、结束标志和最终大小。文件关闭时，系统写入结束标记，刷新所有待写入块，并将最终文件大小写回 inode 记录。读取请求到达后，系统先查询打开上下文读块缓存和原始文件缓存；若未命中，则调用 `READ_OBJECT(data, off, len)` 或等价接口从对象字段读取指定偏移和长度的字节，并将结果返回给上层文件系统调用。

图4 为本发明实施例的覆盖写版本化与历史版本隐藏文件暴露示意图。如图4所示，同一逻辑路径下的不同时间值表示不同文件版本。系统读取普通路径时选择最新时间记录；当用户以写模式打开已有文件时，系统复制必要元数据并生成新的时间记录作为新版本，后续写入均落到新版本对象内容中。目录遍历时，最新版本以普通文件名显示，例如 `sample.dat`；历史版本以隐藏文件名显示，例如 `.sample_1713600000000.dat`。当用户读取隐藏版本文件时，系统从隐藏文件名中解析时间戳，并使用原始逻辑路径和该时间戳定位指定历史版本。

图5 为本发明实施例的会话池、打开文件上下文和多级缓存优化结构图。如图5所示，时序数据库连接模块在进程启动时建立固定数量会话，在一种实施方式中该连接模块为 IoTDB 会话池，文件系统操作通过租约对象临时获取会话并在操作结束后归还。打开文件上下文保存版本时间、路径、父目录、当前长度、读缓存、待写入块和关闭收尾状态，在一种具体实现中可命名为 `OpenFileCtx`，使一次文件会话中的读写状态集中管理。inode 写回缓存以路径为键保存文件或目录元数据，并合并频繁属性更新；目录子项缓存保存目录到子项列表的映射；原始文件缓存以版本时间和路径为键保存小文件或整文件内容；打开上下文读块缓存保存会话内局部读取结果。通过上述缓存分层，系统能够减少重复 `getattr`、`readdir` 和对象局部读取产生的数据库访问。

在上述实施方式中，本发明通过时序数据库核心表统一承载标准文件系统元数据和对象内容，通过 FUSE 保持 POSIX 文件接口兼容，通过对象内容偏移读写提高大文件处理效率，通过覆盖写版本化机制提升写入安全和历史可追溯性，并通过会话池、打开文件上下文和多级缓存降低数据库后端文件系统的访问开销。
