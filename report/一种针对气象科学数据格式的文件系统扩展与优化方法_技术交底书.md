# 专利名称：

一种时序数据库文件系统的气象格式扩展优化方法

# 摘要

本发明提供一种时序数据库文件系统的气象格式扩展优化方法。

所述方法面向 GRIB/GRIB2 等气象科学数据文件在数据库后端文件系统中仅作为普通二进制对象存储时存在的格式语义不可见、内部消息定位困难、整文件传输开销大、重复解码和重复空间计算开销高等问题。所述方法不以时序数据库文件系统的通用目录、普通文件读写和对象内容持久化机制为保护重点，而是在已经能够通过标准文件接口访问时序数据库对象内容的文件系统基础上，增加气象格式元数据扩展、文件内消息索引嵌入、基于数据库用户自定义函数的格式操作下推和多级语义缓存机制。

所述方法包括：在时序数据库文件系统的文件对象记录中扩展气象文件级元数据字段和文件内索引字段；在文件写入、关闭或首次读取过程中识别气象科学数据格式并提取变量、层次、时效、网格、单位等元数据；对文件内部气象消息构建包含语义匹配字段、字节偏移和字节长度的嵌入式索引，并使索引与原始文件对象处于同一文件版本；将气象元数据和索引聚合信息投影为文件系统扩展属性；通过带查询串的文件路径表达消息读取、数值解码、空间裁剪、网格重采样等用户意图；将特定格式操作转换为数据库用户自定义函数或等价数据库侧格式函数调用，使数据库侧根据索引只读取目标消息字节段，并在靠近数据的位置完成解码、裁剪或插值；通过索引缓存、消息字节缓存、解码结果缓存和查询结果缓存复用中间结果。

通过本发明，基于时序数据库实现的文件系统能够在不改变上层普通文件访问方式的情况下，使气象科学数据文件具备元数据可检索、文件内消息可定位、局部数据可读取、格式处理可下推和结果可复用的能力，从而将整文件网络传输转化为索引、消息字节段或裁剪结果传输，减少重复 GRIB 解码、重复空间裁剪和重复网格重采样计算。

# 技术领域

本发明涉及气象科学数据文件管理技术、数据库后端文件系统扩展技术、文件内语义索引技术、数据库用户自定义函数技术、气象网格数据局部读取技术和在线数据处理优化技术，尤其涉及一种在基于时序数据库实现的文件系统中，针对 GRIB/GRIB2 等具有内部消息、变量、层次、时效和空间网格结构的数据格式，提供元数据扩展、文件内索引嵌入、数据库侧格式操作和开销优化的方法。

# 技术背景：

气象预报、再分析资料、数值模式输出和业务网格产品通常采用 GRIB/GRIB2 等气象科学数据格式。该类文件并非无结构二进制对象，而是由多个气象消息或记录组成，每条消息通常包含变量名、预报时效、垂直层次、网格范围、单位、数据点数量和编码方式等语义。业务系统经常只需要读取某个变量、某个高度层、某个预报时效或某个经纬度范围，而不是读取完整文件。

基于时序数据库实现的文件系统能够把目录、普通文件元数据、对象内容和历史版本统一纳入数据库管理，并通过 FUSE 或等价用户态文件系统机制保持普通文件访问接口。该通用数据库文件系统能力可作为本发明的承载基础。但如果气象科学数据文件在该文件系统中仍仅作为普通字节流存储，则仍存在以下问题：（1）文件系统无法直接感知 GRIB/GRIB2 文件内消息边界、变量、层次、时效和空间网格；（2）业务程序需要从数据库后端读取完整文件后在客户端扫描和解码，产生大量网络传输；（3）外部元数据索引与文件版本、覆盖写或删除操作容易不一致；（4）空间裁剪、区域提取和网格重采样常在多个业务入口重复执行，产生重复解码和重复计算；（5）查询结果通常通过专用服务接口返回，难以被普通文件工具、Web 下载和脚本程序统一消费；（6）同一消息、同一裁剪区域或同一插值结果被多次访问时，缺乏与文件版本绑定的语义缓存复用机制。

因此，需要一种与通用时序数据库文件系统相区分的气象格式扩展优化方法。该方法不重复保护通用文件系统对象建模、普通文件读写、覆盖写版本化等底座能力，而是在该底座之上解决气象科学数据格式的元数据扩展、文件内索引嵌入、数据库侧用户自定义函数处理和网络、解码、计算开销优化问题。

# 发明内容：

本发明提供一种克服上述问题或者至少部分地解决上述问题的时序数据库文件系统的气象格式扩展优化方法，以提高气象科学数据文件在数据库后端文件系统中的语义检索效率、局部读取效率、格式处理效率和多入口访问一致性。

本发明的第一方面，提供了一种时序数据库文件系统的气象格式扩展优化方法，包括：

（1）气象元数据扩展：在基于时序数据库实现的文件系统对象记录中，除普通文件路径、大小、权限、时间属性和对象内容字段之外，扩展气象文件级元数据字段。所述气象文件级元数据至少包括变量类型、层次类型、层次数值、预报时效、空间范围、网格尺寸、数据单位、数据点数量或格式版本中的一种或多种。所述扩展字段与原始文件对象使用同一逻辑路径和同一文件版本标识关联。

（2）文件内索引嵌入：在文件写入、关闭或首次读取过程中，识别目标文件是否属于受支持的气象科学数据格式，并调用对应格式适配器解析文件内部消息、记录、变量块或数组块。系统为每个内部消息生成一条索引记录，每条索引至少包括语义匹配字段、消息在原始文件对象中的字节偏移、消息字节长度和格式版本。所述索引以紧凑文本、结构化字段、索引列或索引对象的形式嵌入同一文件对象记录或同一文件版本关联记录中，使文件内容、元数据和文件内索引保持版本一致。

（3）扩展属性投影与语义检索：将气象文件级元数据和文件内索引聚合信息映射为文件系统扩展属性。外部程序可通过 `listxattr` 和 `getxattr` 读取气象语义信息；Web 或命令行检索工具可递归遍历目录并读取扩展属性，实现按变量、层次、时效、区域、单位或格式字段的文件级语义检索。该检索过程不要求客户端解析完整气象文件。

（4）虚拟文件查询构造：允许用户在真实文件路径后追加查询串，以链式函数表达消息读取、数值解码、空间裁剪、区域提取和网格重采样等操作。系统打开该路径时不要求目录中真实存在查询结果文件，而是解析查询串、加载与目标文件版本对应的文件内索引、匹配目标消息并构造只读虚拟文件上下文；后续 `getattr` 和 `read` 调用返回由索引定位和格式处理得到的字节流。

（5）基于数据库用户自定义函数的格式操作下推：将用户查询中的特定格式操作转换为数据库用户自定义函数或等价数据库侧格式函数调用。所述函数根据文件版本、对象内容字段、消息偏移、消息长度和查询参数，仅读取目标消息字节段，并在数据库侧或靠近数据库的数据处理层完成 GRIB 解码、空间裁剪、区域提取、网格重采样或双线性插值。对于二进制消息读取，函数可直接返回目标消息字节段；对于数据读取，函数返回解码数组或裁剪、插值后的结果字节流。

（6）面向开销节约的语义缓存：系统维护索引缓存、消息字节缓存、解码结果缓存和虚拟查询结果缓存。缓存键包含逻辑路径、文件版本、消息偏移、消息长度、解码参数、裁剪区域、插值参数或查询串，避免不同文件版本和不同处理参数之间结果混淆。通过缓存命中，系统减少重复索引解析、重复对象字节读取、重复 GRIB 解码、重复空间裁剪和重复网格重采样。

通过上述方法，本发明能够在不保护通用数据库文件系统底座的前提下，把气象科学数据格式的内部语义扩展到基于时序数据库实现的文件系统中，使普通文件路径既能表示原始气象文件，又能表示内部消息和格式处理结果；能够通过文件内索引和数据库侧函数下推，将客户端整文件下载和离线解析转化为数据库侧消息定位、局部读取和结果返回；能够显著节约网络传输开销、解码开销和计算开销。

# 具体实施方法

下面结合附图和实施例，对本发明的具体实施方式作进一步详细描述。所述实施例用于解释本发明，而不是对本发明的限定。

图1 为本发明实施例一种时序数据库文件系统的气象格式扩展优化方法的总体架构图。如图1所示，该系统包括作为承载基础的时序数据库文件系统层、气象格式扩展层和查询处理优化层。时序数据库文件系统层用于提供普通文件路径、目录、对象内容字段、文件版本和标准文件接口；该层可采用 Apache IoTDB 与 FUSE 组合实现，也可采用其他具有对象字段和标准文件接口映射能力的时序数据库文件系统实现。气象格式扩展层包括格式识别模块、格式适配器、元数据扩展模块、文件内索引模块和扩展属性模块。查询处理优化层包括虚拟文件查询模块、数据库用户自定义函数模块、格式解码与处理模块、语义缓存模块、Web 访问模块和跨文件导出模块。

在图1所示架构中，通用时序数据库文件系统层负责提供普通文件读写和对象内容持久化，本发明的改进点在于：当文件被识别为 GRIB/GRIB2 等气象科学数据格式时，系统在同一文件版本上增加气象元数据字段和文件内消息索引，并将用户对内部消息、裁剪区域或重采样结果的访问表达为普通文件路径查询。上层脚本、Web 下载和第三方程序仍使用 `open/read/getattr/listxattr/getxattr` 等文件接口，但返回内容可由气象格式索引和数据库侧格式函数动态生成。

图2 为本发明实施例的气象元数据扩展与文件内索引嵌入流程图。如图2所示，当文件写入、关闭或首次读取时，系统根据文件后缀、文件头魔数、格式标识字段或适配器探测结果判断文件是否属于受支持气象科学数据格式。若属于受支持格式，则系统调用对应格式适配器解析文件级元数据，并对内部气象消息或数据记录生成索引。若格式无法识别或解析失败，系统仍保留普通文件读写能力，但不启用气象格式扩展能力。

在 GRIB/GRIB2 优选实施例中，格式适配器为 GRIB 适配器，流式写入器可命名为 `GribWriteStreamer`。写入数据块到达后，系统将其追加到滑动窗口，并在窗口中扫描 `GRIB` 魔数字节序列，确定候选消息起点；随后读取候选起点后的 edition 字段，判断该消息为 GRIB edition 1 或 edition 2。对 edition 2，系统读取消息头中的 8 字节总长度；对 edition 1，系统读取消息头中的 3 字节总长度。若窗口内已经包含完整消息，则系统取出该消息字节，并调用 GRIB 解析库创建消息句柄；若消息尚未完整到达，则系统保留未完整消息尾部等待后续写入。

对于每条完整 GRIB 消息，系统从消息句柄中读取 `shortName`、`stepRange`、`typeOfLevel`、`level`、`step`、`unit`、`Ni`、`Nj`、`numberOfDataPoints`、`globalDomain` 等字段，并生成一行紧凑 JSON 索引。该索引至少包含消息语义字段、消息在原始文件对象中的偏移 `of`、消息长度 `ln` 和 GRIB edition `ed`。例如，索引行可表示为 `{"sn":"t","sr":"0-3","tl":"isobaricInhPa","lv":500,"st":3,"u":"K","gd":"global","ni":1440,"nj":721,"np":1038240,"of":0,"ln":845120,"ed":2}`。系统将该索引写入文件对象的 `index` 字段或与该文件版本关联的索引记录，并将文件级元数据写入扩展元数据字段。由于索引记录保存的是消息偏移和长度，后续访问目标消息时不需要重新扫描完整 GRIB 文件。

图3 为本发明实施例的基于数据库用户自定义函数的虚拟查询、格式处理和缓存复用流程图。如图3所示，用户可在真实文件路径后追加查询串表达数据访问意图。查询串至少包括读取函数，也可以包括空间裁剪函数和重采样函数。系统打开该路径时，将真实文件路径与函数链分离，确定目标文件版本，加载该版本对应的文件内索引，按照用户指定的变量、层次、时效、单位、网格或格式字段匹配目标消息。

如图3进一步所示，匹配到目标消息后，系统将查询计划转换为数据库用户自定义函数或等价数据库侧格式函数调用。对于 `function=read,type=binary` 查询，数据库侧函数根据文件版本、对象内容字段、消息偏移和消息长度仅读取目标消息字节段，并将该字节段作为虚拟文件内容返回。对于 `function=read,type=data` 查询，数据库侧函数读取目标消息字节段后调用格式解码器得到数值数组；若查询链包含 `crop`，则根据消息网格元数据和用户输入的经纬度范围计算裁剪窗口，仅输出裁剪区域数据；若查询链包含 `interp`，则对裁剪后或全场数据执行双线性插值或其他重采样操作，并返回指定输出网格的结果字节流。

在 GRIB/GRIB2 优选实施例中，用户可通过如下路径表达查询：`/mnt/dfs/sample.grib2?function=read,type=binary,shortName=t,level=500` 用于读取匹配消息的 GRIB 二进制字节；`/mnt/dfs/sample.grib2?function=read,type=data,shortName=t,level=500?function=crop,lat0=10,lon0=100,lat1=20,lon1=120` 用于读取解码后并裁剪的数值数组；`/mnt/dfs/sample.grib2?function=read,type=data,shortName=t,level=500?function=crop,lat0=10,lon0=100,lat1=20,lon1=120?function=interp,interp=bilinear,outNi=256,outNj=256` 用于在裁剪后执行双线性插值并返回指定输出网格。上述路径对应的结果均表现为只读虚拟文件。

如图3进一步所示，系统将文件级元数据和索引聚合信息映射为扩展属性，例如变量名、层次类型、时效范围、空间范围、网格尺寸、单位、消息数量、索引键集合和索引值集合。外部程序调用 `listxattr` 时，系统返回该文件可用的语义属性名；调用 `getxattr` 时，系统读取对应元数据字段或索引聚合值并返回。Web 检索模块或命令行检索模块可递归遍历目标目录，对受支持气象科学数据文件读取扩展属性，并将满足全部条件的文件作为搜索结果返回。

如图3进一步所示，系统维护索引缓存、消息字节缓存、解码结果缓存和虚拟查询结果缓存。索引缓存复用已解析的文件内索引和消息匹配结果；消息字节缓存复用目标消息字节段；解码结果缓存复用已解码的数值数组；虚拟查询结果缓存复用裁剪或插值后的最终结果。跨文件导出工具根据路径前缀、变量、层次、时效、版本去重策略或其他气象语义条件筛选候选文件，读取每个候选文件的文件内索引，定位目标消息，调用数据库侧格式函数执行解码、裁剪或格式处理，并将结果写出为本地数据文件、批量打包流或供 Web 下载的虚拟结果。

在上述实施方式中，本发明通过基于时序数据库实现的文件系统承载原始文件对象，通过气象元数据扩展使文件级语义可检索，通过文件内索引嵌入使内部消息可直接定位，通过数据库用户自定义函数或等价数据库侧格式函数使空间裁剪、区域提取和网格重采样等特定格式操作靠近数据执行，通过语义缓存复用索引、消息、解码数组和处理结果。与客户端整文件下载后离线解析相比，本发明能够减少完整文件在网络中的传输，避免重复扫描和重复解码未命中的消息，并减少多次执行相同裁剪或插值造成的计算开销。
